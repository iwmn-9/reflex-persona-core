# 単一予測と本人の判断の接続

Pythonの研究候補。安定版とRustは変更していない。採用済みの構成ではない。

学び方を変えた256条件の長期比較では、予測が正確になっても利益が落ちる例があった。同じ本人・状況で再生すると、本人のPolicyは成長側を選んでいるのに、読みを採用する追加の0.05差分条件がその選択を止めていた。さらに、選択を変えない場合にも新しい予測のcontextを次の判断段へ渡していなかった。原因の全記録は、別候補の[完走・因果監査](https://github.com/iwmn-9/reflex-persona-core/tree/c68898d/evidence/long_horizon/adverse_transfer/reactive_ablation)にある。

変更は共通の判断ループだけ。公開ルールの条件付き結果が完全にあり、比較用の助言ではなく単一の応答予測を返す場合、その予測で本人のPolicyを一度適用する。追加の読み採用差分条件を外す。性格・主義・リスク評価・Policy内の行動変更コスト・進捗マスク・読み取り予算は残す。競合する助言や不完全な予測の採用条件は変更しない。ゲーム名・行動名による分岐はない。

捨てるのは、単一予測に対して暫定判断を追加で固定する抑制。得たいのは、学んだ確率がその人物自身の判断へ一貫して届くこと。ただし、行動の揺れや長期損失が増える可能性があり、意味の整合だけで性能改善とはしない。

`plan.json` と `registration.json` を実行前に固定した。4分野・4人格・4変化パターン・4乱数の256条件を各128手で再実行し、元の予測器と形の転用を行う予測器を別々に比べる。以前の256条件を原因調査に使用済みなので、これは開発確認であり独立確認ではない。16本の応答列を分野・人格間で共有している。識別子 `stable` はこの実験内の「元の予測器」を指し、変更していない配布安定版という意味ではない。

毎手の保存復元、人格不変、実際の学習履歴と世界乱数を監査する。比較では予測列そのものが同一であることも確認し、選択経路だけの変更を分離する。分野別・人格別・変化パターン別の損益と全悪化条件、行動変更回数を残す。この確認だけでは採用せず、H32での長期比較と既定の独立40条件は別に必要。

256条件・512実行・65,536手は完走・監査済み。変更前の同じ予測器の実行と対にして比較した512対すべてで、予測列・実応答列が一致した。共通する登録ソースの変更は `reflex/decision_loop.py` だけ。学習器の精度向上による差とは混同しない。

元の予測器を使い、接続だけ変更した結果は次のとおり。点数は各ゲームの宣言した正規化目的点で、勝率ではない。

| 分野 | 平均の実得点差 | 条件付き期待増分差 | 改善／同等／悪化 |
| --- | ---: | ---: | ---: |
| 競り | +0.0050010681 | +0.0020526886 | 35 / 3 / 26 |
| 戦闘 | +0.0001220703 | -0.0001546224 | 2 / 61 / 1 |
| 賭け | +0.0028483073 | +0.0027628581 | 29 / 26 / 9 |
| 資源 | +0.0164794922 | +0.0169372559 | 56 / 3 / 5 |

資源と賭けは4人格すべての平均で両指標が改善した。競りは挑戦型の実得点平均と自己主張型の期待増分平均に悪化があり、分野平均で隠さない。資源の行動変更回数は平均12.80→19.06、競り90.53→88.63、賭け10.86→9.95、戦闘2.30→2.30だった。行動変更の増減だけを賢さや無駄の指標とはしない。全16分野・変化群と全16分野・人格群、個別悪化は `comparison/comparison.json` が正本。

原因調査の慎重な資源NPCは、元の予測器では170→197、形を転用する予測器では136→201の最終資金になった。後者の128手すべて安全取引だった状態は、12手の安全取引と116手の成長行動へ変わった。性格を挑戦型へ変えた結果ではなく、同じ人格の採点へ学んだ予測を通した結果。ただし、この既知1条件を一般化の証拠には数えない。

**両予測器とも全分野非悪化の条件は未達で、候補は保留。** 独立40条件へは進めない。形の転用を加えた構成でも戦闘が悪化しており、新しい学習機構を足すだけで解決したとは言わない。

元の予測器で戦闘のどちらかの指標が悪化した5条件すべてを調べた。即時判断だけでは、早期の推測によって有限の行動資源の使用順が変わり、使い切った後は補充を選べず待ち続ける。H32への接続を切った診断なので、この停滞をH32の失敗とは呼ばない。最初の行動分岐と最初の資源枯渇を双方の実経験から再生し、同一の本人・公開状態・ルールだけを重複排除して10件の既存H32照会を完了した。全ての資源枯渇局面で補充を選べた。最初の分岐では変更前の待機から変更後の補充へ変わるため、長期成績が同じ・改善するとも保証しない。記録は `known_roots/`。これは局面診断であり、新しいH32採用比較を開始したものではない。

得られたのは、学習を判断へ接続する共通の修正と、3分野での128手の利益改善。捨てたのは二重の暫定判断維持。ただし、戦闘の不足と一部の人格・変化条件の悪化が残る。安定版への統合やRustへの移植は行わない。

固定版 `38a01cab3e38cab05d769437a301bc9671f199e9` の全体検査は1,326件を完走し、19件スキップ、1件失敗。失敗は「追加した継続候補は最良値を変えない」という確率的なテスト例の前提で、実際には最良値と品質下限がともに向上した。元の世界は保持して既存候補の評価不変と下限非低下を検査し、悪い候補追加の検査は確実に不利益な準備環境へ分離した。変更した2件は通過。実験結果を生んだ実行コードは変更していない。比較の再集計も保存ソースから再検証し、数値・圧縮明細は完全一致した。詳細とログ末尾は `post_study_validation.json`。固定実験の再生には上記コミットまたは `source.zip` を使う。

同じ完全履歴を32手ずつに分けた会計も `phase_accounting.json` に残した。元の予測器での条件付き増分差は、資源が全4区間で正（+0.004171、+0.002688、+0.005528、+0.004551）。競りは前半が負、後半が正（-0.000591、-0.001875、+0.003447、+0.001072）。戦闘の差は初期32手だけに残り、以後は双方とも補充へ進まない。これは実際の経路・資源差を含む会計で、後半を独立標本や学習能力の因果推定にはしない。512対すべてで区間の和と元の全長差が一致した。

即時判断のみの失敗は保持したまま、同じ学習器を使う H32 統合構成を別に [consistent_horizon](../consistent_horizon/REPORT.md) へ登録した。先行計画に書いた実験着手条件の不備と訂正理由を明記し、元の10条件・独立40条件の採用基準は変えていない。安定版へ昇格したという意味ではない。
