# Prospective finite case diagnostics

This changes execution order only. Current Q/G/N studies keep their existing
whole-cohort prerequisites. No prospective cohort or diagnostic has started.
`verification.json` is the qualification authority; implementation and historical
qualification are retained in `qualified_execution.zip`.

After a candidate passes all development, loss, personality and source/package
requirements, use the existing strict confirmation bridge to prepare its original
40 conditions / 120 executions inside that frozen worker's ignored `results/`.
Do not change its scientific source, seeds, controls or criteria.

Use the qualified local `confirmation_case_batch.py` beside its resolver, cache
and monitor modules. Commands are finite and never watch or schedule later runs.

1. **Before any world worker starts**, run `register --queue QUEUE --driver ORIGINAL_DRIVER --probe ORIGINAL_PROBE --powershell PWSH --output PROTOCOL_JSON`.
2. Start the original registered world queue normally. When every arm of a case
   has finished, run `stage --protocol-path PROTOCOL_JSON --case CASE_ID --output CASE_FOLDER`.
   This checks inactive writers, source registration and complete factual history.
   Stage nonloss cases too; final reconciliation requires the entire universe.
3. When local CPU capacity is free, run `run --root CASE_FOLDER --workers N` with
   1–4 available slots. Existing valid files are retained. After interruption,
   inspect parent/children before passing the exact status SHA via
   `--acknowledge-interruption`. Do not kill or duplicate scientific work.
4. After **all** original worlds finish, create the full scientific archive and
   use the unchanged `prepare_registered_loss_roots.py` with
   `confirmation_loss_resolver.py` to prepare the full final diagnostic queue.
5. Before that final driver starts, run `install --archive FULL_ARCHIVE --execution FINAL_QUEUE --cases ALL_CASE_FOLDERS`.
   Every case/control/root/input/probe is reconciled with the complete archive.
   Identical cached bytes are installed only after all checks pass. Missing
   diagnostics remain required, and different existing bytes are never replaced.
6. Run the unchanged full diagnostic driver and collector. Preserve
   `casewise_protocol.json` and `casewise_handoff.json` beside their final archive.
   The original adoption and personality review still follows; neither casewise
   completion nor numeric passage alone adopts a candidate.

Offline qualification reused 10 fully completed historical cases / 2,560 actual
steps and 72 already-computed diagnostic files. All 72 bytes passed the unchanged
final preparer, driver and collector, including 12 original forecast controls.
No new NPC simulation, new diagnostic forecast or wall-time speedup was measured.
