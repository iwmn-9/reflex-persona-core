# 将来の通常判断と、既存の一手の目的評価の接続

Python研究候補。安定版とRustを保持する。先行する転用予測候補と判断接続候補は、元の全10条件と全悪化の診断を終え、不採用として保存済み。本候補は準備・回帰・人格の機能確認を通過し、元の10条件をPC上で比較中。採用・独立40条件の開始はしていない。

元の転用予測候補は全10条件を完走・監査しても賭け分野の基準を満たさなかった。慎重型の条件付き資金差−9は、利益になる準備を3回少なく選んだ会計に対応する。予測誤差の平均改善だけでは、判断の改善にならなかった。

その96手目を元のLinux環境・人格・実際の学習履歴で再現した。目的の平均だけを本人の採点へ揃える診断は、この局面を含む9予測で選択を変えなかった。既存の厳密な同点補正も、予測内で観測した33個の本人状態で選択を変えなかった。どちらも今回の解決策として重ねない。数値と元の選択の完全一致は [診断記録](causal_diagnosis.json) と [保存物・診断ソース](causal_diagnosis.zip) に残す。

準備の収益を受け取る将来の手番では、粗い即時効果が上限で揃い、追加で利益を狙う手の差が見えにくくなっていた。本人は様式の差も評価して待つ方を選んでいたため、完全に同じ効果・様式にだけ作用する同点補正では解決しない。実履歴96手と予測内6手を厳密に再生し、同じ将来の本人へ既存の一手の目的評価を渡した別コピーでは、待つ選択から本人の予測に沿う選択へ変わった。人格の重みや本物の未来は渡していない。

候補 `tail_purpose_reflex=True` は、既存の二手回復が起動しない通常の将来判断へ `owned_rollout` の一手評価を接続する。32手の長さ、予測標本、転用学習器、仮想学習、主義・欲求・様式・リスク評価、反復を試す候補は保つ。ゲーム名・行動名による分岐はない。既定値はFalseで、採用済み構成は変わらない。実験実行器の `transfer_purpose` だけが明示して有効化する。

得たいものは、収益の粗い表現に埋もれた選択の差を、既にゲーム側が提供している目的評価から使えるようにすること。捨てる候補は、正の即時効果があるだけで将来の本人の目的評価を省く近似。追加計算が必要になり、一手評価も実際の32手再計画と等しいわけではない。局面の選択変更だけを長期改善とは扱わない。

短い検査で当初「5操作の準備をH8でも選ぶ」と想定したが、従来構成も選ばなかった。反復候補が途中の次周期へ支出する既存の候補不足が理由で、H10では旧・新とも準備を選んだ。H8の同等結果も検査へ残し、この限界を新構成で解決したことにはしない。

別の接続修正候補は、全10条件で競りと賭けの分野別基準を満たさなかった。6悪化条件の12局面・72評価も完走監査済み（[全結果と原因分析](https://github.com/iwmn-9/reflex-persona-core/tree/9638501/evidence/long_horizon/consistent_horizon)）。本候補はその構成へ重ねず、転用予測候補の未来の通常判断にだけ目的評価を接続する。元の開発10条件・新しい同条件の対照・全悪化レビュー・予約済み独立40条件の基準を変更せず、登録を分ける。局面だけ、途中結果だけ、単体検査だけでは採用しない。

同じ96手目で32手予測を完了した [比較](root_comparison.json) では、従来側は元の判断・目的値・選択監査・候補対応・予測歩数を完全再現し、`bet:2` を選んだ。接続側は `bond` を選んだ。人格は同じで、外側の継続経路に記録された歩数は両方2880。この計数には内部の追加一手評価を含まず、計算量が等しいという意味ではない。既に見た局面での予測修正であり、二つの異なる予測の目的値を実現利益の改善として比較しない。入力・590ファイルの固定ソース・両予測・監査を [保存物](root_comparison.zip) に含める。

この比較の実測は従来140.58秒、接続側941.26秒だった。新しい一手評価は予測内でも仮想的な本人の更新まで行うため、計算費用は増えた。現在は判断品質を優先するが、単に準備を選ぶようになったことと、採用できる総合的な改善は区別する。

準備の回帰確認には、元の12種類の課題・128手・収益変化の時刻・人格・H32設定を使った。`tools/run_purpose_tail_preparation.py` は旧・新の新規対照を取り、元の条件を削らず、全24実行の実世界・学習履歴・保存復元・変化前の情報遮断を監査する。新側の全最終スコア差が−1e−12以上という基準も維持した。これは機構の回帰確認で、開発10条件や独立40条件を代替しない。

実装09def09のローカル全体回帰検証は1,327件・失敗0で完走した。19件はLinuxのプロセス制御と任意の麻雀環境への依存によりスキップし、実行ソースと全3,196追跡ファイルの不変も照合した（[記録](validation.json)、[ログとソース対応表](validation_execution.zip)）。これは回帰検証で、準備課題の全24実行、開発10条件、独立40条件の完走を代替しない。GitHub Actionsは使わない。

後続の比較準備では、既に検査済みのH16対照と全登録ソースの保存処理を接続した。4環境で元のH16との実学習・判断・世界乱数の一致、新候補の連続／中断再開の一致、既定40条件の数値基準と欠落拒否、元の判断器の回帰を含む22検査が成功した（[接続確認](confirmation_connection.json)）。これは既存の比較器の移設で、候補の判断方式は増やしていない。準備12条件の完走・監査後にのみ開発10条件を固定登録する。

実際の新候補H32・元の3標本を、従来の人格課題にも通した。達成重視は利得、配慮重視は利得を一部譲る手を選び、同じ配慮型でも欲求モードでは利得を選んだ。行動名の変更、実観測後のJSON保存復元、本人状態も一致した（[人格の機能確認](persona_contract.json)）。4分野の長期世界では十分表せない他者配慮の接続確認であり、人格パラメータが同じというだけで機能の維持を主張しない。長期品質の採用判定は別途必要である。
