# 公開された相手の行動を覚える：予測の改善は局所的、意思決定には未接続

基線はmain `b1c0b711a2b3786a7206853593fa5598cb1b0bbc`。前周期の固定済みbaseline 64局だけを再解析した。**今回も意思決定への統合はしない。** 人格、価値階層、本人の経験学習、目的選択、既存forecast、root completionの既定値は変更していない。

## 結論

- 前周期の敵競合16件中10件の確率0は、重みの問題ではなく仮説の行動範囲不足だった。状態取り違え・未来情報・行動合法性の問題は検出されなかった
- 全合法移動候補を分母にすると、観測記憶の混合は対照・留保の両方で一様分布と同じ混合の記憶なし版よりBrier/log lossが低い。ただし対照steady・留保growthでは悪化し、対照の**局を等重みにした平均**も記憶なし版より悪い
- 全敵行動の予測では、対照の記憶版は一様分布より悪い。校正も一様分布より常に良いわけではない。占有確率を改善したことを、相手全般を理解した・人格を推定した・対策が勝敗を改善した、と読み替えない

事前の集計上の必要条件だけは通過したが、これは導入判定ではない。設計段階から統合禁止とし、結果後の混合率変更・追加seed・有利な条件の選別は行わなかった。

## 10件の確率0は何だったか

[diagnosis.json](diagnosis.json) は全10件の公開状態・合法手・両仮説・公開後の実手・実手評価の内訳を保存する。

全件がgoal=`both`、敵が未secureの状態。既存の2仮説はいずれも未達routeの先頭`eliminate`を使い、射撃を予測した。実reference敵は未secureなら中央確保を優先し、中央への合法移動を選んだ。**10件すべてで2本の共同仮説全体が同じ**だった。等重みを変えても、両方にない中央移動へ確率は付かない。

- 816回の本人の実移動、16件の敵競合、10件の確率0。16件は局/tick/目的セルで別事象であり、同じセルへ進む本人複数体の二重計上ではない
- 10件は7局、同一公開状態をまとめると7種類。enemy_convergence/bothで6件、mixed_junction/bothで4件
- 対照705tickの保存pre-state/仮説/実手を再照合。保存forecast先頭2,424件が一致。実手3,745件・仮説手3,272件すべて合法
- 実敵の1,636判断を元の公開状態から再現。対照の方式間650共通状態で実敵手も一致し、本人の最初の行動差4件でも敵手は同じ

実controllerの再実行はこの**事後診断だけ**に使った。新予測器は実controller、隠れた種別、実seed、実乱数、現在の公開後の手を呼ばない。

## 予測対象と記憶の境界

予測するのは「公開pre-stateと、前tickまでに公開された相手の意図から、次にどの合法行動を選ぶか」。実敵はコード上、現在の本人の選択を引数に受け取らない。過去の本人の選択は次の公開状態を変えるので、その反応は含まれる。本人が別の手を選んだ世界、同時手を見られる敵、別の方策へ切り替えた場合の反応までは推定していない。

占有という名前でも、ラベルは**敵が同じセルへ進もうとする意図**。規則解決後に実際にそのセルへ入ったかではない。共同衝突なら全員失敗するため、この区別は必要。

各局の各観測個体に専用の記憶を作り、その内部も相手個体ごとに分離する。同じ公開履歴を全員が見れば数値は同じになるが、記憶の共有ではない。局を越えて同一人物だと推定したり、別人の癖を流用したりはしない。死亡した観測者の更新は止まる。

記憶は、武器あり/合法射撃あり/中央内の8状況と、guard/reload/shoot/heal＋移動の9種類の公開幾何変化、計13分類の固定表。過去の公開手だけを加算し、毎tick 0.9倍に減衰させる。現在合法な同分類の手へ等配分し、合計2の一様事前量を足す。結果の成功・失敗による重み付けや、自動的な信頼度はない。反復そのものを飽き・無駄とみなす罰もない。

この分類は手設計で、目的を理解したモデルではない。例えば同じ「secure距離が縮む移動」に複数の行き先があれば区別しない。相手同士の協調も学ばない。

## 結果を見る前に固定した比較

[design.json](design.json) と [preregister.json](preregister.json) に、ソース・設計・入力SHA-256、64局のID、方式を保存してから実行した。入力は前周期の128局からbaselineの48対照＋16留保を固定抽出しただけ。今回の留保は**前周期の留保軌跡の再利用**であり、新しい独立な外部検証ではない。

Fは既存の2つの共同仮説の等混合、Uは敵個体ごとの全合法手一様分布の積、Lは個体別観測記憶分布の積。

|方式|共同分布|
|---|---|
|uniform|U|
|fixed|F|
|fixed_coverage|0.8F + 0.2U|
|cold_memory|0.4F + 0.6U|
|observed_memory|0.4F + 0.4L + 0.2U|

fixedの占有確率は2つの共同仮説の中でそのセルを狙う割合を直接数えた。個体別周辺確率の積に置換して相関を壊していない。L/Uの独立性は明示的なモデル仮定。全合法手への支持を足すだけならfixed_coverageでも達成できるため、cold_memoryとの比較で「記憶を使った分」を別に測る。

## 全合法移動候補での評価

1,015tick、9,414個体/合法目的セルの試行。実際に選ばなかったセルと、敵が規則上届かないセルも含めた。対照6,922件中68件、留保2,492件中13件が敵意図あり。対照68件は局/tick/目的セルでまとめると58事象。同じ敵移動先を複数の本人個体が合法候補として持つ場合は別試行として数える。これらは可能な衝突ラベルであり、実衝突数ではない。同じ公開状態や複数個体のセルが相関するので独立標本数ではない。

### 集計に隠れる悪化

- 対照steady：記憶Brier 0.008441、cold 0.008308、一様0.008284。記憶はcoldよりlog lossも悪い
- 留保growth：記憶Brier 0.008626、cold 0.007390、一様0.004954。log lossも0.024762で、cold 0.022514、一様0.019372より悪い。留保reference相手の集計も、Brierはcoldより悪く、両損失は一様より悪い
- 対照48局を等重みにした記憶−coldの平均Brier差は **+0.000230**。26局改善・13局悪化・9局同値。長い局/合法候補が多い局を重く数える全試行平均と結論が違う
- 留保の記憶−coldは等重みでも−0.000030（12改善・3悪化・1同値）。ただしfixed_coverage相手には4局改善・11局悪化・1同値で、平均改善を多数の局の改善と言わない
- 対照のECEは記憶0.00522より一様0.00380が低い。固定区間の校正図は記述的検査であり、校正済みとの認定ではない

全条件・全人格・全局を [evaluation.json](evaluation.json)、[per_game.json](per_game.json) に保存した。人格間を同じ行動へ揃える評価ではなく、各人格が作った同一公開軌跡で予測器を比べた。

## 例の10件、方針変化、反復

実際に選んだ移動だけの10件の確率0は、Uを足した全方式で正になる。これはcoverageの機構による。tick0の4件はまだ公開履歴がなく記憶とcoldが同じ0.1。growth592の連続する中央への意図ではtick1/2の確率がcold 0.0857/0.0750から記憶0.2000/0.2455へ上がった。一方、mixed_junctionのcare/steady tick2では0.0750→0.0506、ego tick7では0.0750→0.0406へ**下がった**。正支持と適切な確率配分は別。

switch相手は既存driverがtick8で変化する。切替時刻/種別を予測器へ渡さず、報告の分割にだけ使う。切替後230行動の記憶log lossは0.7589（cold 1.2150、一様1.6125）。しかし同じ切替後700候補の占有は既存fixedがBrier/log lossとも0で、記憶は0.000687/0.004971へ悪化する。方針変化を検出できた・全場面で追従できた、とは言わない。

単体検査では同じ合法戦術の反復で予測質量が上がり、反転後に旧戦術から新戦術へ移り、元の戦術の再出現も学べることを確認した。これは固定した小さな合成履歴での機構検査。実ゲームの成功経験や長期戦術学習を証明するものではなく、記憶APIには成功/報酬/人格を入力する欄もない。

## 方法上の参考と再現

[Dawid (1984)のprequential原論文](https://people.csail.mit.edu/jrennie/trg/papers/dawid-prequential-84.pdf) を、予測→公開結果で採点→次の予測へ更新という評価境界の参考にした。[Gneiting & Raftery (2007)](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf) に従い、Brierとlog lossを確率予測の適切なスコアとして使い、校正と区別した。手設計の分類・混合・減衰や性能保証がこれらの論文から導かれるわけではない。外部コードは導入していない。

    python -m unittest discover -s tests -v
    python -m reflex.observed_opponent_experiment --input /path/to/controlled_congestion/trajectories.jsonl --output reflex_artifacts/observed_opponent_replay
    python tools/summarize_observed_opponent.py --input reflex_artifacts/observed_opponent_replay --output /path/to/new_summary
    python tools/opponent_memory_cost.py --output /path/to/new_memory_cost.json

入力原始軌跡のSHA-256は前周期verificationと一致する必要がある。前周期の再現はcontrolled_congestionの説明を参照。既存preregisterを上書きしない。原始予測JSONL（約6MB）、全局の詳細校正区間、全tick費用は生成物とし、公開evidenceには全局・全方式の損失、分割合計の校正区間、入力/出力ハッシュを残した。
