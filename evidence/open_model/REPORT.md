# 用意した仮説の外を学ぶ：実装と実証

2026-10-14。既知のゲームルールと本人に見える情報から、人物類型の候補にない行動分布を獲得する任意部品を実装した。単に既存仮説の信用を下げるだけでなく、観測した条件と結果の関係を記憶し、次の予測・反射判断・本人の先読みに利用する。

**予測能力の追加は成立した。全般的な賢さの安定は未達。** 戦闘・資源管理・賭けの診断環境では平均目的値が改善した一方、オークションでは予測が改善しても目的値が悪化した。全NPCの既定設定へ一律に採用せず、接続できる選択肢として公開する。勝ち手・節約係数・ゲーム名による分岐を共通コアに追加して、この負けを埋めてはいない。

## 得たものと費用

- **得たもの**：固定された人物仮説の混合で表現できない新しい傾向、状況と直前行動の組合せ、持続する変化や元の傾向への復帰を、実際の公開観測から学べる。最初から正解の新タイプを登録する必要がない。
- **維持したもの**：固定人格・主義の係数、本人の観測範囲、合法ルール、個体ごとの知識所有。想像した結果を実体験へ書き込まない。同じ予測更新を仮想分岐と実行後に使う。
- **支払う費用**：初動の不確かさ、学習に必要な観測、条件を細分化するほど経験が薄くなること、有限の記憶から古い経験が落ちること。既存仮説が正しい条件では柔軟性の小さな予測費用もあった。
- **見送ったもの**：既定構成への一律採用。新しい特徴・未知のゲームルール・因果関係の自動発見、長期技能記憶、頑固さによる解釈の偏りとの統合は今回の実装範囲ではない。

仕組み・API・責務の正本は [OPEN_MODEL.md](../../docs/OPEN_MODEL.md)。実装は `reflex/adaptive_dynamics.py`、ゲーム側接続は `tools/open_model_games.py`。

## 観測できた行動

戦闘の最初の人格・最初の登録シード（growth、71000、shift）では、次が起きた。以下の番号はログの0始まり。

1. 第11ゲームの冒頭に一度だけ例外的な敵行動が出た。この一回では従来の攻撃方針を捨てなかった。
2. 第12ゲームで敵の傾向が持続的に変わった。最初の2手は以前の攻撃を続け、次の2手は防御し、最後の2手は新しい傾向に合う攻撃へ移った。
3. 第13・14ゲームは、その新しい攻撃を使って敵を倒した。用意した仮説だけの比較役は以前の攻撃を続け、これらのゲームで倒された。

実際の変化時刻や正しい対処法を判断器へ渡してはいない。人格係数も変えていない。ただし、これは6手の自作診断環境の観測例であり、人間水準の戦術や面白さの証明ではない。[該当する全比較役の記録](examples.json) を保存した。

## 比較設計

4環境は、3人オークション、複数資源の生産・投資、攻撃と防御、賭けと見送り。オークションの決済には既存の `contests.settle` を使い、その他は小さな診断用ルールを作った。全て最大6手。適用可能なルール・結果の列挙はゲーム側が担当し、共通の学習器・判断ループはゲーム名を知らない。

比較する予測器：

| 方式 | 機能 |
|---|---|
| library | 既存の名前付き仮説だけを、観測前の予測成績で再配分する |
| marginal | 新しい分布を学ぶが、状況・直前行動で条件分けしない |
| long | 条件分けはするが、128観測の一つの窓だけを使う |
| adaptive | 条件の部分集合と8・32・128観測の窓を比較する今回の構成 |

`library` は従来の `HypothesisTracker` そのものではない。従来の responsive 設定との比較は、別途同じ公開観測列に対する**予測だけ**で行った。従来方式より全ゲームで強いという比較ではない。

| コホート | 条件 | キャンペーン | ゲーム数 | 判断数 |
|---|---|---:|---:|---:|
| development | 既知・新傾向・状況依存・途中変更・雑音・単発例外。4人格、2シード、4方式 | 768 | 18,432 | 105,740 |
| holdout | 自分の直前行動への反応・元への復帰・2特徴の相互作用。4人格、4シード、4方式 | 768 | 18,432 | 107,547 |
| planning | 状況依存・途中変更。4人格、1シード、2方式、2手先 | 64 | 768 | 4,407 |
| 合計 | 同一キャンペーン内では経験を持ち越す | **1,600** | **37,632** | **217,694** |

development/holdoutは1手先の判断。holdoutは別のシードに加え、賞品・公開状況の順序と実過程の雑音率も変更した。学習器の係数は初実装から変更していない。これは設計者が作った追加変化条件であり、未知の実ゲームによる第三者評価ではない。planningのシードと試合数は他コホートと異なるため、表を横に比べて先読み深さの効果を推定しない。

同じ条件・人格・シードの比較役と対応付ける。1キャンペーンの反復ゲームを独立した汎化事例として数えない。主指標は各ゲームが宣言した**目的値**で、勝率ではない。ゲーム間で尺度が違うため、異なる行の値の大小に意味はない。

## 目的達成度：改善と悪化の両方

以下は adaptive − library の平均目的値。正が改善。括弧は対応するキャンペーンの「改善 / 同値 / 悪化」数。

| 環境 | development：各48組 | holdout：各48組 | 2手先：各8組 |
|---|---:|---:|---:|
| オークション | **−0.2144**（0 / 0 / 48） | **−0.3661**（0 / 0 / 48） | **−0.1236**（1 / 0 / 7） |
| 戦闘 | +0.2712（38 / 2 / 8） | +0.1322（35 / 1 / 12） | +0.4332（8 / 0 / 0） |
| 賭け | +0.4188（43 / 0 / 5） | +0.2645（43 / 0 / 5） | +0.6467（8 / 0 / 0） |
| 資源管理 | +0.2310（44 / 1 / 3） | +0.1395（44 / 0 / 4） | +0.3410（8 / 0 / 0） |

条件分けを取り除いた marginal と比べても、両コホートの4環境で平均目的値は上がった。holdoutの平均差はオークション +0.0622、戦闘 +0.0684、賭け +0.1346、資源管理 +0.0465。ただし個々のキャンペーンでは負けもあり、全局面で有益な万能分割ではない。

長い窓だけの long に対しては、holdoutで戦闘 +0.0315、賭け +0.0603、資源管理 +0.0274、オークション −0.0133。短期と長期を混ぜるだけで資源配分の欠陥が治るわけではない。全条件・全人格・各シードの数値と対比較は [summary.json](summary.json) にある。

### オークションで何が起きたか

developmentでは全6種類の変化条件で予測の平均log lossが改善したが、目的値は全48組で悪化した。holdoutでも48組すべて悪化した。**相手を読めることと、その読みを将来の予算配分へ使えることは別**だった。

developmentのadaptive全48キャンペーンについて、最終ゲーム開始時の同じ公開局面を再構築した。実際の法則を知って終局まで目的値だけを最大化する評価器を、判断器とは切り離した診断用に計算した。これは利用可能な強さの上限を調べる補助であり、実際のNPCへ渡していない。

- 1手先では48局面中42、2手先では43で、選んだ初手がこの目的専用評価器の最善手から外れた。
- 同じ予測結果から人格のstyle項だけを除いても、初手が変わったのは1手先で4局面、2手先で8局面だった。
- 1手先から2手先へ伸ばして初手が変わったのは3局面だった。
- pilotの新傾向の一例では、1手先・2手先とも入札3を選んだ。終局までの目的値は入札1が約0.324、入札3が約0.130。styleを除いても入札3だった。

したがって少なくとも、この悪化を「人格が目的を犠牲にした」とだけ説明できない。短い評価期間で目先の入札を魅力的に評価し、残り予算の機会価値を捉え損ねることが、有力な改善対象になった。ただし診断は最終ゲームの初手であり、キャンペーン全損失の因果分解ではない。真の法則を知る評価器は、同じ知識・同じ人格の将来行動の再現でもない。[48局面の診断](auction_development_diagnostic.json)、[pilot診断](auction_diagnostic.json) を公開する。

読む範囲を少し増やすだけではこの局所的な行き詰まりを解消できなかった。資源の制約と将来の機会価値を扱う研究へ角度を変えた。次の候補は、ゲーム専用の節約係数でなく、残す資源を将来の候補へ結び付ける汎用的な評価契約。調査元と適用限界は [実装文書](../../docs/OPEN_MODEL.md#採用範囲と研究) にまとめた。今回は新しい資源価値推定器までは実装していない。

## 「知らないタイプを学んだ」の切り分け

ゲーム中の行動選択とは独立に、7種類×8シード×384観測を用意した。4方式で224ストリーム・86,016予測。さらに既存responsive方式を同じ56ストリーム・21,504予測で比較した。以下は平均log loss（小さいほど良い）。

| 観測列 | library | 既存responsive | adaptive |
|---|---:|---:|---:|
| 既存仮説と一致 | 0.0870 | 0.1842 | 0.0894 |
| 新しい結果へ偏る | 4.9581 | 1.1206 | 0.1162 |
| 途中で持続的に変わる | 2.5238 | 0.6826 | 0.1539 |
| 変化後、元へ戻る | 1.7232 | 0.5210 | 0.1535 |
| 2特徴の相互作用 | 2.5362 | 1.1474 | 0.1531 |
| 一様な雑音 | 2.6041 | 1.2433 | 1.1331 |
| 渡した特徴からは判断不能 | 2.5916 | 1.1572 | 0.7659 |

既存responsiveは候補の外れを検出して不確かにする働きを持つ。今回の追加は、その先で実観測から別の分布を形成できること。従来方式と今回方式では平滑化等も異なるため、表全体を一つの機能だけの効果とは解釈しない。同じ実装から機能を外した marginal/long の対照も併記している。

相互作用は、各特徴だけを見ても説明できないXOR条件。adaptiveは0.1531、条件分けなしは0.7508だった。判断不能条件で「学習したから正解が分かる」とはならず、後半の最大予測確率の平均は約0.54。一様雑音では約0.41で、根拠のない強い予測を維持しなかった。予測器の重みは真の原因や変化点の確率ではない。

全成績・記述的な回復遅れは [controls.json](controls.json)。これは公開結果が見える診断であり、選ばなかった行動の結果が見えない一般の探索問題を解決した証拠ではない。

## 接続・検証・復元

- ローカル全 **1,013テスト成功**。うち今回の15件は、新傾向、条件依存・相互作用、雑音・持続変化、合法集合の違い、観測前採点、保存復元、他個体・仮想分岐への非汚染を検査。終局まで読む小さなケースでは、学習を含む予測と実行時の本人の方策が一致することも照合した。
- 主コホートの **217,694判断すべて**について、保存した公開状態から予測・実観測の生成・記憶更新・目的値を再生照合した。判断器そのものを全判断で再実行した検証ではない。初手の再実行はオークションの診断に含む。
- 予測専用224ストリーム・86,016観測も独立再生した。既存responsiveの比較は別の凍結済み実行記録として保存した。
- 通常の `DecisionLoop.decide` と `decide_batch` へ接続し、4環境×4人格の冷間・学習後 **32局面**で個別選択と4個体バッチの一致、記憶の非汚染、人格係数の不変を確認した。学習後には戦闘の攻撃、資源生産、賭け先などが変わった。大量NPCの速度ベンチマークではない。[接続記録](reflex_connection.json)。
- 初回pilotの4件の失敗は、公開状態のtuple/list保存復元の不一致。アダプターの公開辞書をJSON型へ正規化して再実行し16件全て完了した。初回失敗を [initial_failures.json](initial_failures.json) と `pilot.jsonl.gz` に保持した。pilotと探索的な2手先試験は主コホートの集計から除いた。

各実行前のコードをコピーして凍結し、入力条件・ソース指紋・圧縮前データの指紋・ソースの変更版を保存した。[registration.json](registration.json)、[provenance.json](provenance.json)、[source_variants.json](source_variants.json)、[verification.json](verification.json) を参照。圧縮軌跡は展開後の元データ一致を確認している。既存の過去証拠は変更していない。

CPUのみで実行。Colab・GPU・LLMは使用せず、実行時の新しい依存や利用許諾ライセンスは追加していない。

## 到達点

「用意した候補が外れたら、不確かになる」から、**「既知ルールの範囲で、観測から新しい条件付き傾向を獲得して、本人の判断へ使う」**へ進んだ。人格の特性を学習器が書き換える設計にはしていない。

一方、予測が良くなった結果を長期の目的へ変換する賢さ、より大きい・部分観測の実ゲーム、ゲームをまたぐ技能転移、面白さ・人間らしさの評価は残る。今回のオークションの退行を理由に、予測器の成功を全般的知能の完成と呼ばない。
