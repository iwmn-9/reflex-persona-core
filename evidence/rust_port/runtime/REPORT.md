# Rustの判断部品をゲーム全体の実行へ接続する

2026-10-24。`reflex-runtime` を実装した。通常判断の実行に限り、
**観測→複数NPCの並列判断→世界での実行→全員の反映→世界とNPCの一体保存**を
`GameSession<World>` から扱える。即時判断v1の数式・人格・乱数・保存形式は変更していない。
ローカルWindowsの統合・同等性検査は完了。Windows/Linux CIは公開後の確認待ち。
全人格AI、学習、長期判断のRust化を完了したという認定ではない。

## 得たものと追加しなかったもの

一人用の判断部品に加えて、全NPCを同じ世界版で扱う責務がまとまった。
共有資源の競合による未実行と、実行したが結果が悪かった行動を区別する。
一人分の実行報告が不正でも先に他のNPCだけ反映しない。
途中参加/退出、休眠、意図のリセット、世界変更後の古い提案の拒否を備える。
保存は盤面・世界乱数・全NPCを一緒に扱い、期待する人格・目的・名簿と照合する。

今回見送ったのは、検証中の学習・予測器・32手読み・感情/関係更新を先に固定すること。
Python側の機能を削ったり、将来価値を即時効果に丸めて互換と見なしたりはしていない。
人格の設定や強さを変える調整、共通実装内のゲーム名/行動名への分岐もない。
長期判断の独立40組は既存の凍結ソースで別途動作を継続しており、この移植検査を合算しない。

## 実測

| 確認 | 結果 |
| --- | --- |
| Pythonとの比較 | 競り・資源管理・戦闘・ギャンブル × 4人格 × 3主義方式 × 2世界乱数 = 96経路 |
| 継続判断 | 各128手、12,288判断で行動・対象・意図状態・乱数・読みの採否・候補可否が一致 |
| 数値採点/特徴量 | 最大絶対差0（許容上限2e-12、離散結果の不一致は許可しない） |
| 実世界 | 毎回の遷移と最終盤面、世界乱数がPythonと一致 |
| 保存復元 | 3,072バッチで世界とNPCを保存/復元。24回Rustプロセスを終了・再起動 |
| 並列/入力順 | 1/2ワーカーと入力逆順を交互に使用。Rust検査では1/3/4ワーカーも比較 |
| Rust API | 即時判断10 + 統合10 = 20検査成功、clippy警告0 |
| 人数境界 | 10,000人の一括判断、順序、全員の保存復元。人数超過を拒否 |
| 共有世界の接続例 | 経済・戦闘の各6人×256tick、通し実行と毎tick復元が一致 |

[登録した条件・ソース](registration.json)、[集計](result.json)、
[96経路の記録](runs.jsonl.gz)、[API・接続例の結果](checks.json)。
Rust 1.99.0、NumPy 2.3.5、Windows x86-64で確認した。
各NPCの物理世界は独立したものを四つずつ同じruntimeへ入れている。
共有世界の競合を測った96試合とは呼ばない。共有世界は別のRustアダプター試験で確認した。

経済の接続例は1,520行動を実行、共有資源の競合で16行動を未実行とした。
戦闘は1,536行動を実行した。どちらも途中復元後の続きが一致した。
接続例の効果見込みは手設計であり、戦闘での停滞改善や人格AIの強さを評価するものではない。

初回の96経路も通過した後、OSのワーカー生成失敗をpanicでなくエラーとして扱い、
起動済みのワーカーを全て回収する処理を追加した。最終ソースで同じ96経路を再確認し、
入力と展開後の軌跡が初回と一致した。これを独立192経路には数えない。

## 受け持つ境界と残る制約

`GameSession` は新しい世界を作ってから全員の判断状態を反映する。
観測失敗、ルール実行失敗、実行報告の不足、不正な世界版で、世界とNPCの両方が不変なことを検査した。
別個体/別runtimeへの提案流用、削除・再登録後の提案流用、古い世界、誤った行動/対象、
重複/不足した実行報告、保存破損/版違い/人格違い/名簿違いも拒否する。

この原子性は純粋な世界アダプターを前提にする。ゲームが先に外部エンジンや共有可変状態へ
副作用を出した場合の巻戻し、ファイル/DBの永続化は実装していない。
直接接続用 `Runtime` の全員反映もNPC状態の範囲であり、外部エンジンの実行を保証しない。
チェックサムは破損検知で、改ざん認証やセーブの巻戻し防止ではない。

世界側には本人の知覚・合法手・効果見込みを作る負担が残る。
人格を評価する機構は保ったが、人間らしい行動や長期の賢さが今回向上したわけではない。
速度は未測定。10,000人は機能検査の上限であり、毎フレームの実時間処理を保証しない。
Rustは現時点でスレッドを使える64bit Windows/Linuxを検証対象とする。Wasm/モバイル/特定ゲームエンジンは未検証。

利用方法・状態の意味・責務は [runtime README](../../../rust/reflex-runtime/README.md) に一本化した。
実験の判断器はPythonのまま。両crateは `publish=false`、利用許諾は未設定のまま。
