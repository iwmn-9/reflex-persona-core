# Rustへ実学習と長期候補の選択を統合した結果

2026-10-26。実装コミット `bb7082832ec9298aac802fd2c7a006f78358a46a`。
採用済みPython構成の公開条件付き予測を、`reflex-owned::Owner` と
`reflex_runtime::learning::LearningSession` へ接続した。
人格・主義の係数、採用基準、ゲーム側のルールは変更していない。

## 完成した単位とPythonに残る部分

Rustが固定人格、実際の行動結果の記憶、公開事象の分節予測、欲求圧、目的進捗を所有する。
通常判断に加え、累積効果の単位と目的許容幅を含む長期候補から、本人の価値観で実行する一手を選ぶ。
結果の受理、入力検証、途中状態の拒否、世界とNPCの保存復元までを同じ実行単位で扱う。
複数NPCの最後の結果だけが不正でも、世界や他のNPCを先に更新しない。

32手先の候補生成・未来の本人の再判断はPythonの `FixedHorizonOwner` に残る。
`NativeOwnedBoundary` はRustが持つ**現在の実経験**から予測用の本人を復元する。
独立した生身のPython NPCを並行して維持する必要はない。
ゲームの観測・合法手・既知の条件付き効果・目的評価と通信の実装はホストが提供する。
汎用とはこの契約を別のゲームへ接続できる意味であり、ゲームルールを自動理解する意味ではない。

これは完全なRust単独H32探索器の完成ではない。通常の学習付き判断はRust単独で動くが、
今回接続したH32候補生成にはPythonが必要。実験中の探索、社会記憶、別の予測器、
経路選択や価値提案はPythonに残し、未対応の設定は黙って省略せず拒否する。
対応構成・上限・APIの正本は [所有者API](../../../rust/reflex-owned/README.md)。

## 判断・学習・復元の比較

許容条件は離散判断と状態の一致、数値差 `2e-12` 以下、Rust自身の保存前後の完全一致。
一つの不変なPython予測候補を、PythonとRustの二つの選択器へ渡して比較した。
予測候補を生成する本人の履歴はRust由来で、照合用Python NPCの履歴を流用しない。
物理世界はRustが選んだ行動で進め、毎回Pythonとの実学習状態を照合する。
独立した二つの探索器の同等性や、新しい知能向上を測った実験ではない。

| 検証 | 結果 |
| --- | --- |
| 長い履歴からの接続 | 競り・資源管理・戦闘・ギャンブル × 4人格、16条件すべて完走 |
| 継続判断と保存復元 | 各164手、計2,624回。一致。31手ごとに実プロセスを再起動、計80回 |
| 長期候補からの選択 | 各条件で129回の実観測後にH32を1回、計16判断。一致。その後も学習・復元を続ける |
| 行動・対象・意図・乱数・候補可否 | 不一致0 |
| 採点・特徴量 | 最大絶対差 `8.881784197001252e-16` |
| 予測確率 | 最大絶対差 `2.220446049250313e-16` |
| 学習状態の数値 | 最大絶対差 `1.1102230246251565e-16`。離散状態は一致 |
| 保存復元 | 各段階でRust状態が完全一致。世界と設定に結び付いた復元を使用 |

H32を2,624回すべて実行したとは数えない。この移植検査は長い実履歴・128件の履歴窓を
またいだ学習と、その本人を使うH32選択の接続を確かめるもの。
各ゲームの4人格は元の定義をそのまま使用し、観測事象を23手ごとに切り替えた。
世界の乱数を変えて都合のよい経路を選び直す処理はない。

gzip内は相対ファイル名から元JSONへの対応。実行途中の集計を成功数に含めていない。

## 修正した不整合と得失

検証中に、終局が早い世界でも32手分を要求してしまう検証条件と、
未行動の本人の未使用緊急度の初期表現がPython/Rustで異なる問題を修正した。
終局後の行動を作らず有効区間を使い、未行動状態を正規化して同じ本人へ結び付ける。
人格や判断の閾値を動かして不一致を隠してはいない。

**得たもの**は、人格を維持した実学習・判断・保存をRustが一貫して管理する実行単位と、
実経験からPythonの長期候補へ戻る明示的な接続。既存の即時判断API・保存版は保持した。
**今回見送ったもの**は、変更余地のある探索器全体のRust移植、追加の人格機構、
専用ゲーム調整、エンジン別バインディング、速度向上の主張。
代償としてH32利用時のPython依存とホスト側の接続実装が残る。

今回の同等性検査は、既に完了したPythonの独立40組による品質採用を置き換えない。
元の [安定版採否](../../stable_release/RELEASE.md) と長期品質の既知の限界はそのまま残る。

## 再現

実装コミットをcheckoutし、Rust 1.99.0とNumPy 2.3.5を使用する。
各出力先は未作成のものを指定する。検証器は実行前後のソースhashを照合する。

```sh
cargo build --locked --manifest-path rust/Cargo.toml -p reflex-owned --example owned_verify
cargo test --locked --manifest-path rust/Cargo.toml --workspace
python -m unittest tests.test_native_owned -v
python tools/run_rust_owned_parity.py --output FRESH_INTEGRATION --workers 4
python tools/verify_rust_owned.py --output FRESH_HISTORY --steps 160 --profiles 4
python tools/verify_rust_owned.py --output FRESH_TERMINAL --steps 4 --profiles 4 --horizon-steps 1
python tools/verify_rust_owned_prediction.py --output FRESH_FACTORS
```
