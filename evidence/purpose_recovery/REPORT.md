# 目的の決着と、準備から行動へ戻す接続

## 結論と採否

資産・生存・途中の進捗を、そのまま目的達成とみなさない共通契約を追加した。同じ人格の先読みを毎手やり直す経路へ、実際の準備完了・有限待機・停滞による欲求圧力も接続した。

目的評価を修正した方式では、資源管理の実達成がcontrol/confirmationとも3/16から12/16へ増えた。confirmationの戦闘勝利は1/24から6/24へ増えた一方、敗北も1から3へ増え、生存は23から21へ減った。資源の不足やego人格の敗北にも悪化条件がある。**賢さの安定を達成したとは認定しない。**

目的評価だけの方式で移動往復が消えた条件に、準備解除・停滞圧力まで加えると6回戻った。勝利の上積みもなかった。目的の意味を分離する部品は任意の基盤として残し、追加の監視・圧力をまとめて標準採用することは見送る。標準Policy/Populationの経路は変更しない。

## 得たもの・残したもの・見送ったもの

- 得たもの: 途中の代理値と、ゲーム規則による勝利・敗北・引き分け・最終得点を区別する `Goal`。先読み終点を一度評価し、期間平均によって実勝利の差を薄めない `goal_forecast`。準備の実必要量に達したら待機を解除する既存機能を、今回の再計画経路にも接続した。
- 残したもの: 固定性格、本人の最大主義tier、将来利得への時間選好、死傷・支出・欲求上の損失。目的だけ高い手で主義を強制解除しない。予測が正しいとは限らず、全人格を同じ勝率へ調整していない。
- 見送ったもの: 今回の「目的評価＋準備解除＋圧力」を標準経路へ昇格すること。追加だけで品質が上がるとは確認できなかった。目的の達成を改善するため、生存・一部人格の勝利維持を失った条件も隠さず残す。
- 増えた負担: 終点評価、監視状態、複数モデル分岐の検証が必要になる。今回、速度費用を品質の代用指標にしていない。大量NPC実戦性能は再測定していない。

## 比較条件

同じ公開初期盤面・人格・実seedで、以下の三方式を比較した。

|方式|目的の扱い|実進捗監視・欲求圧力|
|---|---|---|
|old|前回のflow評価・途中代理値|なし|
|goal|即時の目的効果を修正＋終点Goal評価|なし|
|release|goalと同じ|既存の準備解除・有限待機・圧力を接続|

old対goalでは、即時のobjective/achievement/growth効果と終点評価の両方を変えた。したがって終点評価単独の効果とは言えない。release対goalも監視maskと欲求圧力を同時に追加しており、どちら単独の原因かは未分離。

計288エピソード、96組の対応する三方式比較。control/confirmation各144。各split・方式あたり資源16、競り8、戦闘24。人格は既存のgrowth/steady/care/egoの4種で、特性と主義の数値は途中で変更していない。

|環境|control|confirmation|
|---|---|---|
|資源: 科学・文化・勢力の転換|各勝利への準備がほぼ整った状態、期限5round|同じ初期準備、期限6round|
|資源: 複数勝利条件|通常初期盤面、round2で実際に飢饉、期限8|期限10|
|競り: 公開された後続景品|景品8→10、予算6|7→11、予算6|
|競り: 相手の入札変化|8→10→6、予算10、相手3→5|9→12→7、同予算・変化|
|戦闘: 撃破|本人HP3/6、距離2、期限8tick|HP3/6、距離4、期限9tick|
|戦闘: 目前の締切|HP6、距離2、期限1tick|距離4、期限1tick|

資源の他3人はwaitする。戦闘は既存3v3エンジン中、各陣営1体だけを生存させた条件。各方式の戦闘24件には1tick締切8件を含み、多くが引き分けになる。一般の多人数競争・チーム戦の性能を表す分母ではない。

予測期間6手、目的許容幅0.15、監視grace/repeat_limit各2、圧力grace2。モデル戦闘seed820–823と、実seed control200/201・confirmation210/211を分離した。非戦闘は各splitの先頭seedだけ。未発生の飢饉・入札変化・景品変更設定をscope/観測へ混ぜないことを入力全体の一致検査で確認した。

機能確認にはcontrol配置の一部を使用した。時間選好・通常checkpoint復元・相打ちの引き分け分類の不備を修正し、未完の旧出力を退避した後、最終ソース・全比較条件・確認条件を `preregister.json` へ固定した。公開した288件の結果を見て係数を調整していない。小規模に作成した確認条件であり、代表的な未見ゲーム強度の証明ではない。

## 結果

資源の「不足」はゲーム内の累積shortages。競りは公開初期景品総量で割った本人の実得点の8件合計。戦闘は実勝利・実敗北・本人の生存・A→B→A型の移動戻りを別々に数えた。戻りだけで無意味な停滞と断定しない。ジャンル間で得点の合計を共通の賢さへ換算しない。

|split|方式|資源達成/16|資源不足|競り得点合計/8|戦闘勝利/24|敗北/24|生存/24|移動戻り|
|---|---|---:|---:|---:|---:|---:|---:|---:|
|control|old|3|1|4.3333|2|1|23|22|
|control|goal|12|10|4.5556|2|2|22|0|
|control|release|12|10|4.5556|2|2|22|0|
|confirmation|old|3|18|4.7302|1|1|23|18|
|confirmation|goal|12|0|4.7302|6|3|21|0|
|confirmation|release|12|0|4.7302|6|3|21|6|

資源の改善は、転換準備がある12件で全て達成したことによる。複数勝利条件・飢饉の4件では、いずれの方式も勝利0。この差から「一般的な資源運営が完成した」とは言えない。controlの不足1→10はegoの複数条件ケースに集中し、confirmationでは同種の不足18→0となった。期限が変わると安全性の結果も変わり、安定した緊急対応は未達。

人格別の戦闘内訳は次の通り。各人格・split・方式6件。

|split|人格|勝利 old→goal→release|敗北 old→goal→release|移動戻り old→goal→release|
|---|---|---|---|---|
|control|growth|0→1→1|0→1→1|10→0→0|
|control|steady|0→0→0|0→0→0|8→0→0|
|control|care|0→0→0|0→0→0|4→0→0|
|control|ego|2→1→1|1→1→1|0→0→0|
|confirmation|growth|1→2→2|0→0→0|4→0→0|
|confirmation|steady|0→2→2|0→0→0|7→0→3|
|confirmation|care|0→2→2|0→0→0|7→0→3|
|confirmation|ego|0→0→0|1→3→3|0→0→0|

steady/careが勝てる場面は増えたが、egoのcontrol勝利減少・confirmation敗北増加は残った。弱い人格を救う代わりに別の人格を壊してよい、とは扱わない。生存と撃破の合理的な譲歩か、予測・評価の不備による敗北かを次に分ける必要がある。

releaseのmask適用記録は戦闘control38、confirmation25、未解決は1/0。資源・競りの適用記録は0。これはmaskが作動した回数であり、選択が変更された回数や成功した介入の数ではない。資源/競りでは明示的な準備解除・有限待機の接続を確認できたが、追加による得点改善はなかった。confirmationの移動戻り6はsteady/care各3で、圧力と実行時の監視が未来モデルに再現されていないことも原因候補になる。

## 共通部品とゲーム側の責任

`purpose_plan.py` にゲーム名・勝利規則は内蔵しない。ゲーム側は目標ID、終局判定、途中代理値、候補の実効果、待機/準備の意味、実観測feedbackを供給する。科学・文化・勢力のルート選択や撃破・競りの採点は今回のadapterにある。ルールだけを覚えれば自動的に全ゲームへ強くなる学習済みモデルではない。

Goalはrunningの代理値とsuccess=1/failure=-1/draw=0を分離し、競りはscoredの実得点を使用する。相打ちはゲームの引き分けとし、本人死亡の損失は人格のflowへ別に残す。勝利/引き分けを長い期間の分母で薄めない一方、本人の主観的な終点利得には実モデル手数までの時間割引を残す。正の予測はconfidenceで縮めるが、負の見込みを自信のなさで消さない。

全モデル候補から本人の最大主義tierを先に維持し、その中で目的許容幅を使う。主義による損な選択は表現できる。一方、この許容幅は欲求側の譲歩を制限するため、狭くすれば人格差を減らす可能性がある。0.15はゲーム側が制御できる今回の固定設定で、心理学的な正解ではない。

`ProgressConfig(preserve_persona_tier=True)` は、停滞maskが元の主義tierを全て消すときに強制変更を留保する。この設定を普通のwatch checkpointへ保存し、DecisionLoopがbase watchとして復元しても維持する。既定false・旧checkpoint互換を保持した。`flow_rollout` の任意assess追加も未指定時の既存挙動を変えない。

core/runtime/judgment/decision_loop/deliberation/intertemporalと3種の実ゲーム規則は、基点 `c110b1b4bfe2e1430de98870752580b3961f31ec` からバイト不変。progressとflow_rolloutの追加は明示的な任意機能。未来の本人は依然、同人格の即時Policyで近似しており、将来の進捗監視・圧力・経験更新までは再現していない。実行時の完全な自己モデル、遅延成果の学習・忘却、複数人の共同計画は未完成。

## 再現・監査

```text
python -m reflex.cli purpose-recovery --output FRESH_ROOT
python tools/audit_purpose_recovery.py FRESH_ROOT/purpose_recovery
python -m unittest discover -s tests -v
```

既存のpreregister/trajectory/evaluationがある出力への再実行は拒否する。公開ファイルは本報告・evaluation・preregisterの3つ。大きな実軌跡と開発途中の出力はローカルに保持し、配布しない。ソース凍結はpreregisterの各reflexモジュールhashで照合する。base欄は実験を開始した時点のGit HEADで、変更後の公開commitの代用ではない。

同じ凍結条件のcontrol144件を直列で完了後、残りconfirmation144件だけを独立CPUプロセス4個で実行し、元の順序へ戻した。条件・源・seedは変更していない。競りとseed付き戦闘各1エピソードの全記録が直列/別workerで一致することを別途確認した。これは独立ゲームの実行並列化で、大量NPCの一世界内並列性能の証明ではない。

独立監査で288件・1366実ルール遷移を再生し、427回の実progress/pressure更新・checkpointと最終集計を照合した。引き分けは155件（相打ちも含む）。有限の解除条件を持つwait Activity宣言は266件で、成功した待機や独立した解除の件数ではない。実軌跡SHA256は `ca88b60b451685e06d4fd9f0d7b3a2aacb3028044b1e702f73a050a5f7cb3deb`。

新規13検査を含む569テストを実行し、14件の任意麻雀依存テストをskip、失敗0。追加検査はGoal/終局の矛盾拒否、期間・時間選好・confidence、主義tier保持、checkpoint、実準備解除、未発生条件の観測非漏洩、相打ちと締切、競りの実回収を含む。

実行はローカルCPUのみ。Colab/Drive/GPU/LLM教師生成・モデル訓練は使用していない。Notebookと同梱ZIPはローカルで更新し、Driveへ反映していない。利用許諾は追加しない。置換前の復元手段はローカル `backups/before-purpose-recovery.bundle`。

## 次の急所

まず同じ目標評価のまま、敗北増加と移動戻りを生んだ実行記録を分ける。予測と実行の監視・圧力の食い違い、短い期限で準備を回収できない問題、egoのリスクと生存損失を、別々の比較で切り分ける。全員へ同じ慎重さを強制する修正は避ける。その後、相手が資源を競争する条件や別の複合目的へ広げ、人格を保った賢さの安定を判定する。
