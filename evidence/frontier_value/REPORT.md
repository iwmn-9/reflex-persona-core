# 読みを打ち切った先の価値を補う実装と検証

今回の中心は、短い読みの先を途中代理点だけで採点する弱点。人格係数やゲーム別の勝ち手は追加せず、探索終了時点へ将来の目的値の分布を接続した。**接続部品は成立したが、全ゲームで安定して強くなる標準方式には到達していない。** 通常反射・従来探索の既定を維持し、比較可能な任意機能として保存する。

## 得たもの・採用しなかったもの

- 得たもの：本人の状態を複製して先へ進める `PolicyTail`、事実として完了した試合から推定する `TerminalMemory`、両者を同じ探索へ挿せる契約。予測分布・推定元・推定内の終局率・辞退を観測できる。想像した勝敗を本人の経験へ混ぜない。
- 得たもの：同じ局面での予測精度、選択を固定した比較、実際に再判断しながら対戦する結果を分けた検証。予測が当たることと判断が良くなることを区別できた。
- 採用しなかったもの：近い数値特徴を持つ過去試合の勝敗を、条件変更後も信用する既定。結果の分散を確信度に読み替える処理。試走数・探索深さの一律増加を安定性の保証にする説明。
- 省略したもの：木の外の試走では人格効果列を探索評価へ追加せず、目的値だけを補う。試走内は指定された本人の状態更新に従うが、遠い未来の人格的満足まで評価したわけではない。速度を理由に要求を縮めたのではなく、この区切りの検証対象を目的値へ限定した。

## 実装と適用範囲

接続の正本は [FRONTIER_VALUE.md](../../docs/FRONTIER_VALUE.md)。ゲーム側は公開状態・合法手・遷移モデル・目的の意味を提供する。コアはゲーム名による分岐を持たない。学習済み記憶はゲームごとに作るため、ルールを渡すだけで未知ゲームの賢さを獲得する機能ではない。

推定で終局を見つけても、探索終了時点そのものは `running` のまま。予測を確定勝敗へ書き換えない。終局済みの実状態では推定器を呼ばず、辞退時は元の途中代理値へ戻る。ルール・目的・特徴・継続方策の版を束ねる参照が異なる学習器は辞退する。ただし変更を自動発見する機能ではなく、接続側が正しく版を宣言する必要がある。

## 主比較：終局まで実行した結果

8系統×4人格、開発条件4回・条件変更8回、3方式で 1,152 登録実行。本人が判断したのは 1,092 回、12,615 判断。準備手だけで既に決着した行も保存し、強さの分母から除いた。同じ開始状態・人格違い・決定論的な同一軌跡を独立試合とは呼ばない。

## 停滞から構成を変えた比較

最初の停滞は「終局予測の誤差は下がるのに、選択が安定して良くならない」こと。そこで同じ学習器の係数調整を続けず、(1) 正確な反射継続ならどうなるか、(2) 未来の標本を増やしたらどうなるか、(3) 木を浅くして広い試走へ振り分けたらどうなるか、に切り分けた。

最初に選択が分かれた59局面で候補を固定し、別の64公開シナリオで同じ反射継続を終局まで比較。そのうち試走方式の31局面では標本を2・8・32本へ変えた。これは同じ局面の追試で、新規の独立試合数に加算しない。

|---|---:|---:|---:|---:|---:|

|No Thanks!|8|16|+0.3115|9/0/7|2|
|No Thanks!|32|16|+0.2842|8/0/8|3|

## 正確に計算できる公開問題での切り分け

小さな公開グラフで全分岐を列挙し、実行時に毎回選び直す方策の真の値を計算した。開発256方策、別グラフでの確認384方策。下表は確認群、各長さ8グラフ×4人格＝32条件の平均成功確率。観測した人間相手の勝率ではない。

|方式|長さ6|長さ10|
|---|---:|---:|
|proxy|83.01%|75.81%|
|sampled_tail|87.30%|79.45%|
|sampled_tail8|90.48%|81.16%|
|sampled_tail32|90.72%|80.71%|
|exact_tail|90.77%|79.96%|
|full|94.14%|83.00%|

反射継続を正確に評価しても、実行時に計画し直す本人の価値とは一致しない。確認群の exact_tail では過大予測0状態、過小予測699状態で、実際の再判断が見積りを上回っていた。この不一致をそのまま「過信による悪化」とは呼ばない。将来の本人が改善できる道を過小評価する可能性を含む。32本の試走も8本を一律には上回らない。終局まで同じ本人が選ぶ全探索は整合を保てるが、小さな公開問題以外で同じ計算が可能とは証明していない。

## 学習器の失敗と予測精度

訓練は512登録実行。本人が判断した492実行、重複軌跡を除く465エピソード、4,862 局面。長い試合が多数票を持たないよう、各エピソード一票の重みとする。特徴は既存の共通効果・人格・欲求の要約で、盤面構造や個別資源をすべて残した表現ではない。勝敗が偏る訓練群もあり、『よく起こる結果』を当てるだけで精度が上がる場合がある。

チーム戦闘の条件変更では、記憶器が数値的な支持域内と判定しても誤差が増えた。幾何的に近いことは、ルール・目的・将来方策が同じことを保証しない。実験ではこの弱点を測るため同一ゲーム内の条件変更へ広く転用した。配布契約では参照の不一致を辞退するが、一致させたまま意味を変える誤接続までは救えない。

## 検証と再現

- ローカル988テスト成功。新規の将来価値テスト7件と、資源ゲームの比較相手を同値に保つ検査を含む。25共通接続で50実判断、合法手・保存復元・実ルール再生・実所有者の非汚染を検査。これは25ゲームでの強さの測定ではない。別形式の観測ゲーム4種と閉鎖麻雀には新接続を広げていない。
- 長い実験を完走させるため、同一の公開状態・本人の全保存状態・シナリオ・残り期間の結果を再利用した。資源ゲームの固定比較相手も、意思決定に無関係な凍結相手のフィールドを除く同値計算へ変更。勝ち手や相手の戦略は変えていない。旧出力24エピソード267判断の行動・結果・所有者状態・予測分布を最終コードで再現し、31局面でも元の選択を照合した。
- 計算の中断・再開は完了済み登録行をハッシュで引き継ぐ。別試行へ数え直さない。最初の候補比較59件は保存JSONのlistと実行時tupleを比較した検査側の誤りで全件失敗、正規化した記録で再実行した。無効59件は強さの分母へ加えない。
- 準備中に決着した実行の予測誤差が空になるため、凍結済みの旧集計器は全768実行の完了後に最後の集計で失敗した。完了済み実行を再計算せず、新しい集計器で全登録行を照合して分母を補正した。元ログと凍結ソースは保存。訓練モデルは補正後も完全一致を検査した。
- 各実験の条件・ソースの版・中断履歴は [registration.json](registration.json) と [provenance.json](provenance.json)、検査結果は [controls.json](controls.json)。公開JSONから凍結ソースを復元できる。完全な実行軌跡はローカル `colab-runtime/reflex_verification/frontier_value_*_20261013` に保存し、そのハッシュを公開した。
- Colab・GPU・LLMは使用していない。全機能を同時に有効化した本番NPC、未知ゲーム、人間水準、面白さ、NPC大量実行速度は今回の達成事項ではない。

## 次の急所

ここからの中心は、単に過去の勝敗を増やすことではなく、**同じ状況で別の手を選ぶ価値の差を、欠けた情報と将来の再判断を含めて扱うこと**。共通入力の要約で重要な盤面差を潰していないか、学習対象の継続方策が実際の本人と合っているかを先に確かめる。人格や相手対応を削って数字を整える方向へは進めない。

今回、実装の接続と検証の切り分けは前進した。一方、反射継続を一律の将来価値として採点する路線は、今回の比較では全般的な安定改善に結び付かなかった。追加した部品を無条件に積むのではなく、この不一致を次の設計対象として残す。
