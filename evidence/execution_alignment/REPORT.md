# 予測した継続と実行の対応

## 採用する範囲

任意の行動列記録と、本人/相手を分けたオフライン診断を追加する。人格・主義・経験更新・選択規則は変更しない。`trace_execution=False` が既定で、追加候補/途中評価も従来どおり任意のまま。勝率や知性の改善を主張しない。

再現: `python -m reflex.cli execution-alignment`。出力は `reflex_artifacts/execution_alignment/`。ここへ同梱する正本は `evaluation.json` の集計と限定したtick19の診断のみ。完全な軌跡は再現時にローカルへ生成し、公開版へ同梱しない。

## 固定した条件と非干渉確認

既知の悪化条件 `choke/eliminate/steady/seed180/switch` を再利用した。新規の留保評価ではない。purposeful/optionsをそれぞれtrace off/onで実行し、計4局、142実ルール遷移と426目的更新を独立に再生した。

- purposeful: trace off/onともtick31で勝利
- options: trace off/onともtick40の期限までに勝利せず
- 各対で前後の全公開状態、実行した全員の手、ルールaudit、目的監視の全状態、既存planning診断が一致
- 勝敗、手の回数、経験使用/リセット数、判断回数、モデル遷移数も一致
- すべての選択済み予測標本の根で、本人側の実行手が記録されたモデル根と一致
- JSON保存/復元しても診断結果が一致。固定人格は入力のまま

診断が判断や学習を変えないことの限定した回帰確認であり、全ゲーム/全設定における証明ではない。trace有効時は候補ごとのハッシュ・コピー・保存の費用が増える。性能改善の測定ではない。

## 分離できた不一致

件数は**モデル標本の遷移単位**。同じ実tickを4標本から参照するので、独立な実試行数ではない。

|方式|選択済み予測|標本経路|比較した遷移|同じ公開直前状態|異なる直前状態|同じ状態での本人不一致|同じ状態での相手不一致|
|---|---:|---:|---:|---:|---:|---:|---:|
|purposeful|31|124|673|142|531|15|90|
|options|40|160|897|168|729|8|160|

purposefulでは同じ公開状態・同じ両者の手から異なる後状態になった標本が27件、optionsでは0件。これは原因や乱数への責任を確定する件数ではない。終局後の補完だけの観測単位は52/60、終局時点の不一致は19/3。どちらも実行された行動一致には加算しない。今回は非終局の観測欠測は0件。

### tick19: 相手仮説の不一致

optionsは目的見込み0.4072164→0.4676505を根拠に、本人3人をguardから移動へ変えた。本人の実行手は4標本すべての根と一致した。

実際には相手unit3とunit5がともに `move:6:2` を選んだ。モデルはunit3が `move:6:2`、unit5が `guard` と予測した。現在の公開盤面は同じなので、これは相手行動の同じ状態での不一致と記録できる。次tickから公開状態がずれるため、その後の手の違いを本人継続や相手方策の直接の誤りとは数えない。

purposefulの同じtickでも相手予測は同様に違う。optionsの敗北の唯一の原因がこの不一致だとは示していない。

### tick0の予測、offset1: 本人継続の不一致

両方式の最初の予測で、次tickの公開状態が一致しているにもかかわらず本人の手が違う例がある。モデルの目的向け戦術と実際の人格付き再判断が同じ継続ではないことを、状態のずれとは別に検出した。将来の全手を人格Policyで決めるモデルへ変更したわけではない。

## 安全境界と未完成

run/group/target/unit/start/horizonを検査し、異なる実験/個体群/尺度/時間単位を混ぜない。欠測tickを前に詰めず、行動不明と生存者ゼロを区別する。終局後の実行を拒否する。診断は純粋関数で、個体記憶・信頼・方策を更新しない。

同じ状態・同じ手の一致は、因果的な責任や平均目的予測の正しさ、未知の手への信頼を意味しない。標本の一致率を校正済み確率として使わない。全公開状態を持つ自作戦闘だけの接続であり、不完全情報ゲームは観測履歴を含む別の同等性契約が必要。
