# 二つの予測が両方外れるときの回復

既存の `EventLearner` を、通常判断・実観測・仮想の本人・保存復元へつなぐ `EventReader` を追加した。二つの予測の採否を繰り返すだけでなく、公開経験から別の応答分布を組み立て直せる。人格、ゲームの合法手、物理ルール、目的の定義、採点係数は変更していない。

採用するのは任意の回復経路。すべてのゲームの既定にはしない。予測が改善しても入札の最終得点が悪化し、急変直後の追従にも代償がある。予測の修復と、資源を将来の機会へつなぐ評価は別の課題として残す。

## 得たものと払ったもの

- 得たもの：有限仮説にない応答傾向を、短期・長期・公開特徴別の経験から学び直す実行経路。以前の失敗局面で、同じ本人の予測だけを替えて判断を修正できた。
- 維持したもの：固定人格・主義、動く欲求、進展監視、欠測の区別、モデル分岐の隔離。ゲームごとの有利な手や係数を追加していない。
- 代償：1人につき最大128観測を保持し、複数の予測器を評価する。平常時のばらつきを抑える一方、急変直後の反応が遅くなる場合がある。古い・稀な状況の経験は失われうる。
- 採らなかった案：予測の改善だけで全体を成功と判定すること、入札にだけ別の人格係数を足すこと、予測器を追加すれば長期判断も自動で安定するとみなすこと。

## 何を接続したか

従来の経路は直近4例の分布と有限仮説の分布を比較する。両者が同じ方向に誤ると、比較を正しく実装しても回復できない。

新経路は既存の学習器の設定をそのまま使う。直近8・32・128観測、宣言された公開特徴の組合せ、供給された仮説を、結果を見る前の予測成績で混合する。少量の重みを各予測器へ戻し、以前悪かった方式も変化後に復帰できるようにする。これは [Tracking the Best Expert](https://mwarmuth.bitbucket.io/pubs/J39.pdf) に沿う既存部品の接続で、新しいAI原理の主張ではない。確率の校正や隠れた変化の即時検出を保証するものでもない。

効果が欠測でも公開応答は学習する。未観測の応答や、未選択手の結果を実経験として保存しない。既知のルール内の傾向を学ぶもので、未知のルール・行動・知覚特徴を発明しない。全候補に同じ応答法則を当てられる契約が必要。詳細は [接続仕様](../../docs/PREDICTION_RECOVERY.md)。

## 同じ本人での直接診断

前回の軌跡を完全再生し、その時点までに本人が見た公開応答だけで新予測器を訓練した。問題の局面では盤面・人格・欲求・記憶・進展監視を固定し、予測器だけを交換。比較用の真の確率は採点にだけ用い、NPCには渡していない。

| 条件 | 旧判断 | 交換後 | 同じ本人の即時採点差 |
|---|---|---|---:|
| 慎重な人物の戦闘、tick34 | 防御 | 攻撃0 | +0.246641 |
| 同、tick69 | 二つの予測とも防御 | 攻撃0 | +0.246641 |
| 同、tick106 | 二つの予測とも防御 | 攻撃0 | +0.246641 |
| 成長志向の賭け、tick78・90 | 見送り | 賭け0 | 各+0.579237 |
| 同、tick103 | 賭け0 | 賭け0 | 0 |
| 同、tick105 | 二つの予測とも見送り | 賭け0 | +0.579237 |
| 協力志向の賭け、相手変化直後のtick33 | 見送り | 賭け0 | **−0.228067** |

tickは0から始まる観測時刻。戦闘tick69の応答0の予測は旧基線57.1%、旧候補65.4%、交換後81.6%。実験上の真確率は85%だった。同じ安全志向の評価でも、見込みを修正すると攻撃が有利になる。tick34は旧候補が既に攻撃を提案していたが採用されていなかった例で、二つとも防御だった例と区別する。

最後の反例は、相手が変わった直後にも従来の傾向を信じる代償。NPCは隠れた変化を知らないため、真確率で不利だったことだけを非合理性の証明にしない。即時採点は将来投資や進展マスクを含む最適性の証明ではなく、終局の目的得点とも別。

## 前回条件の再検証

前回と同じ32条件・各128判断。旧方式の32軌跡は、前回保存したものと選択・状態digest・得点が完全一致した。これは既知条件への回帰確認で、新しい留保試験とは数えない。

| 系統 | 改善 | 同等 | 悪化 |
|---|---:|---:|---:|
| 入札 | 2 | 3 | 3 |
| 資源管理 | 8 | 0 | 0 |
| 戦闘 | 6 | 0 | 2 |
| 賭け | 8 | 0 | 0 |
| 合計 | 24 | 3 | 5 |

指標は完了した短い試合の正規化目的得点の平均で、勝率ではない。慎重な人物の定常戦闘は0.376812→0.613333。悪化も保存し、平均の改善で消さない。戦闘の成長志向・定常条件は1試合平均が下がる一方、完了試合が25→27に増えた。試合の長さと観測する世界の時刻も行動で変わるため、平均得点の差だけを純粋な判断ミスの差と解釈しない。

実判断8,192、モデル内判断27,876。同じ行動と観測を与えた仮想本人との更新一致8,192件、保存復元320件、実記憶を汚さない先読み704件を確認。更新の一致は未来予測の正しさとは別の検査。

## ゲームを離した予測試験

8乱数列×応答集合3/5×6条件、各512観測。計96系列・49,152観測。同じ観測列を各方式へ与え、定常、変化と復帰、仮説外の傾向、単発の外れ、雑音、公開手掛かりと応答の関係の反転を比較した。

| 条件 | 旧基線 | 旧候補 | 回復方式 |
|---|---:|---:|---:|
| 定常 | .035414 | .022140 | .002760 |
| 変化・復帰 | .035189 | .051408 | .010120 |
| 仮説外 | .032778 | .138204 | .003975 |
| 単発の外れ | .035667 | .022268 | .002777 |
| 雑音 | .012728 | .019777 | .004913 |
| 手掛かりとの関係反転 | .129268 | .116665 | .014103 |

数値は真分布との平均二乗距離で、小さいほどよい。実現応答に対するBrier score全体ではなく、その期待超過分に相当する。ゲーム試験の保存フィールド名 `expected_brier` もこの距離を指す。真分布は診断だけに使う。

平均だけでは初動の遅れが隠れる。変化・復帰の各変化後8観測では旧基線.07890に対し回復方式.12747。その後の区間は.03163→.00476。単発の外れへの耐性と、急変時の追従を無償で両立したとは言わない。

## 入札で残った限界

先読みを外す16条件の対照でも、目的得点は0改善・13同等・3悪化。全16条件で予測誤差は改善し、本人の即時採点との隔たりは3改善・13同等だった。特に慎重な人物の仮説外条件では目的得点が0.133681→−0.194444へ悪化した。

したがって、問題を短い先読みの標本誤差だけに限定できない。目先の評価が正確になることと、最終目的を達成することが一致していない。残資源を後の機会へ使う評価は次の調査候補だが、この対照だけで悪化の全原因を特定したとは言わない。「慎重な人格の代償」とも自動認定しない。既存の終局評価の簡略接続は、動く欲求・学習記憶を持つ本人をそのまま扱えず、安易に差し込めない。この適用境界を越える評価と本人の接続が残る急所。

悪化例のtick67まで実本人を状態digestごと完全再生し、同じ状態から最初の入札だけ3/4に替える対照も行った。両方とも合法で、進展監視も許可している。以後は同じ人格・欲求・経験を持つ本人が各分岐で学び直して選び、残り5判断を終局まで追う。ここだけは実験上の真の応答法則を世界側に使う診断で、実行NPCへ真の確率を渡す提案ではない。

| 最初の手 | 真確率での本人の即時採点 | 同じ本人の継続後、平均終局目的点 |
|---|---:|---:|
| 入札3 | .005703 | .149450 |
| 入札4（実際の選択） | .069917 | −.306641 |

独立した診断用乱数列の128対で、入札3側は128改善・0同等・0悪化、平均差+.456091、差の標準誤差.012123。価値2の品を資金4で取る手は、直後に来る価値7の品への資金を失う。この局面では予測を真確率へ直すだけでも即時の本人採点は入札4を選ぶ。1,280モデル内判断の局所対照であり、ゲーム全体の最適手、人間らしさ、人格の損失の厳密な分解までは認定しない。`auction_reflex.zip` 内の `horizon_auction_steady_outside_67.json` に全分岐を保存した。

## 広げた比較

共通の不完全な仮説集合を使い、旧joint、本人の選択利益で採否するchoice、学習分布を外したlibrary、今回のrecoveryを比較した。仮説は最初の2応答を優勢とするものだけ。残りの応答もルール上は可能だが、それを優勢とする仮説は渡さない。定常、変化と復帰、仮説外の優勢応答、公開手掛かりとの関係反転を固定した。同じ公開手掛かりは全方式へ渡し、新経路は宣言したカテゴリ特徴として利用する。

開発群は4系統×4人格×4条件、乱数seed43、各方式192判断。同じ本人が短い試合をまたいで経験し、12判断ごとに3手・3標本の先読みを使う。6手以下の試合の反復であり、192手続く一つの世界ではない。choiceに対する目的得点の比較は次のとおり。

| 系統 | 改善 | 同等 | 悪化 | 平均差 |
|---|---:|---:|---:|---:|
| 入札 | 3 | 3 | 10 | −.021340 |
| 資源管理 | 16 | 0 | 0 | +.111263 |
| 戦闘 | 12 | 0 | 4 | +.104855 |
| 賭け | 16 | 0 | 0 | +.197591 |
| 合計 | 47 | 3 | 14 | +.098092 |

choiceに対する予測誤差は64条件すべて改善。即時の本人採点との隔たりは50改善・3同等・11悪化だった。libraryとの比較では目的得点41改善・8同等・15悪化、予測誤差48改善・16悪化。与えた仮説が最初からよく合う条件では、経験から学ぶ部分を足す利益が保証されない。全比較と悪化条件は `summary.json` に保存する。

人格パラメータは固定し、予測だけを勝利志向の採点へ置き換えていない。例えば開発群の資源管理の初手では、全員の同じ予測分布に対して安定志向は交易、ほかの3人格は生産1を選んだ。行動差が残る一例であり、人間らしさの包括的な評価ではない。

開発群の実判断49,152、モデル内判断163,319。全49,152更新の本人一致、1,792保存復元、4,096先読みの隔離を確認した。

開発結果を見る前に予約したseed70/103を使う留保群は、各方式256判断、choiceとrecoveryの比較。学習器の設定は変更せず、4系統×4人格×4条件×2乱数列の128対を完了した。

| 系統 | 改善 | 同等 | 悪化 | 平均差 |
|---|---:|---:|---:|---:|
| 入札 | 10 | 4 | 18 | −.013276 |
| 資源管理 | 32 | 0 | 0 | +.135789 |
| 戦闘 | 31 | 0 | 1 | +.126352 |
| 賭け | 32 | 0 | 0 | +.222904 |
| 合計 | 105 | 4 | 19 | +.117942 |

予測誤差は128対すべて改善。即時の本人採点との隔たりは107改善・6同等・15悪化。最大の目的得点悪化は安定志向の入札・仮説外条件・seed103で.133818→−.094356。戦闘の1悪化は挑戦志向・変化復帰・seed70の.586667→.586538で、小さいが同等へ丸めていない。

留保群の実判断65,536、モデル内判断222,730。全65,536更新の本人一致、2,304保存復元、5,632先読みの隔離を確認した。入札のseed70は賞品順も変更、seed103は開発群と同じ順。ほかの3系統では物理ルールは変えていない。同じseedの人物・条件は乱数列を共有し、128の独立したゲーム世界や統計的有意性の証明とは数えない。

主比較（開発・留保・前回条件・入札の先読みなし）の合計は**129,024実判断、413,925モデル内判断**。全実判断の合法手・公開応答・物理的な遷移・得点を保存軌跡から再計算し、集計と一致した。同じ行動と観測による本人更新の一致129,024件、保存復元4,640件、先読みの実記憶隔離10,432件。pilot、予測のみの系列、完全再生、局所対照はこの数に加算しない。条件間で行動が違うと観測される合法集合や試合の長さも変わるため、同一観測列での予測比較は別のstreams試験に分けている。

## 再現と適用境界

Python 3.12.14、NumPy 2.3.5、WindowsのローカルCPUで実行。新しい依存、Colab、GPU、LLM推論は使っていない。実行用コードはPythonのままで、Rustの安定部品としてはまだ固定しない。

新しい空の保存先を指定して、リポジトリのルートから実行する。

```sh
python tools/run_prediction_recovery.py --root results/development --turns 192 --workers 6
python tools/audit_prediction_recovery.py --root results/development
python tools/run_prediction_recovery.py --root results/holdout --holdout --turns 256 --workers 6 --arms choice recovery
python tools/audit_prediction_recovery.py --root results/holdout
python tools/probe_prediction_recovery.py --root results/streams
python tools/run_recovery_bridge.py --root results/bridge --workers 6
python -m zipfile -e evidence/lifecycle_integration/choice_holdout.zip results/previous
python tools/audit_recovery_bridge.py --root results/bridge --previous results/previous
python tools/run_prediction_recovery.py --root results/auction_reflex --games auction --turns 192 --workers 6 --arms choice recovery --plan-every 0
python tools/audit_prediction_recovery.py --root results/auction_reflex
python tools/diagnose_recovery_horizon.py --root results/auction_reflex --game auction --profile steady --regime outside --tick 67 --roots bid:3 bid:4 --samples 128
python -m unittest discover -s tests -v
```

実験ごとに実行ソースを凍結し、軌跡とハッシュを保存した。各ZIPの `_source` がその結果の実行版。初期pilotは仮想の応答法則を根元の状況で固定しており、最終の公開特徴別予測とは異なるので探索用に限る。開発群実行後にPolicyの8結果上限を明示的に辞退する検査と、同じ公開状態の重複組立てを省く実験コードの変更を加えた。対象4ゲームの応答は最大4個で、最終コードによる開発群の入札1条件192判断は全出力が完全一致。留保群は最終の実行部品そのものを凍結している。

回帰検査は1,097件中1,080成功、任意依存等の17件はskip。新しい接続の7検査はすべて成功。仮説外応答からの判断変更、観測チャンネルの混在、実本人と仮想本人の更新一致、誤った観測の原子的拒否、保存復元、所有と時刻、強制された応答から選好を誤推測しないこと、扱えない列挙の辞退を確認した。実行ログと最終の変更ソースは `final_source.zip`、検査対象ファイルと成果物のハッシュは `verification.json`。

4系統とも既存の短い検証ルールであり、未経験の商用ゲームへの移植証明ではない。対戦相手は指定された隠れた確率過程で、全員が同時に適応する社会世界でもない。全試行で固定人格を保ったことと、人間水準の面白さ・知能を示すことを区別する。関係・感情のあらゆる組合せや、主観的な思い込みの強さとこの学習器の合成も今回の通し検証には含めない。

通常の判断・観測・仮想の本人・保存をつなぐ回復経路は成立した。予測を改善した先の長期目的評価まで一括して安定したとは認めない。次の焦点は、実際に動く本人を維持したまま、残資源と将来の機会を評価へ結ぶこと。ゲーム別の入札補正を足してこの反例だけを消す方向は取らない。
