# 学ぶ本人の継続と長期判断

## 問いと変更

予測器を改善しても、長い実行の目的得点が改善しない原因を、世界の予測と本人の実行に分けて調べる。性格・価値観・Policy係数、公開ルール、目的定義を固定する。競りだけの入札係数、補充などの行動名に依存したコア分岐は追加しない。

`RecedingOwner` は、実観測を解決した `DecisionLoop` から毎回予測を再構築する。未解決の試行のまま次へ進めず、不完全な予測を暗黙に即時判断へ置き換えない。通常の反射Policyは変更しない。毎回の重い探索は今回の知能品質の比較条件であり、大量NPC向けの費用を解決したものではない。

最初の案では、未来の本人は学習するものの、将来の手段選択は即時判断に限定されていた。戦闘で弾薬を使い切った後に立て直せない未来を見積もると、現在の本人が補充を過大評価する。そこで任意の `tail_recovery=2` を用意した。予測内で、合法な候補のどれにも正の即時目的利益を見込めない場合だけ、同じ人格・学習状態による二手の分岐評価を行う。ゲーム固有の「補充せよ」という命令ではない。通常の相手予測、欲求、結果記憶、進展監視を通し、想像上の経験を実本人へ混ぜない。

この二手の評価は有限の近似で、未来の全時点で実際と同じ長い探索を再帰実行するものではない。今回の未来は15手、各経路で最大16回の短い立て直し。全将来の同一性や単調な方策改善を保証しない。目的の条件付き平均による既存の制御変量を、立て直し有無の共通条件にして比較する。標本経路の損失・嗜好・実際の学習イベントは平均へ置き換えない。

## 最初の固定比較

開発seed 43、growth / steady、未知傾向 / 傾向変化と復帰、4ルール、128ターン。世界・負傷・資源・経験は初期化しない。予測方式2種と計画間隔1/7の2×2、16条件・64実行を完走した。全比較は同じLinux環境・同じ公開応答列。

旧予測＋間隔7を基準とした、区間予測＋毎回再計画の結果：

| ルール | 改善 / 同等 / 悪化 | 平均の目的得点差 |
|---|---:|---:|
| 競り | 4 / 0 / 0 | +0.082703 |
| 資源管理 | 4 / 0 / 0 | +0.039388 |
| 戦闘 | 0 / 0 / 4 | −0.076823 |
| 賭け | 4 / 0 / 0 | +0.087240 |

これは開発条件の比較で、勝率でも独立した16標本でもない。目的点の意味はルールごとに異なるため全ゲーム平均を強さとして扱わない。間隔だけを1にした旧予測でも戦闘は4条件とも悪化し、平均差は−0.078776。毎回の再計画だけでは採用できない。

同じ競り16実行について、検証側だけが真の応答分布と将来の変化を知る有限Bellman参照と照合した。実際に通った各状態での目的機会損失の合計は、4条件平均で旧予測・間隔7が0.134058、区間予測・間隔7が0.125190、旧予測・間隔1が0.090011、区間予測・間隔1が0.072152だった。完全情報・目的だけの参照との差であり、人格の正当な支払いと未観測の変化を知れなかった損も含む。すべてを知能不足とは扱わないが、予測器の更新だけで実行の取りこぼしが消えないことを調べる材料になる。

この退行を受け、先に開始していた独立確認 run 38992195728 は中止した。予定224実行中、保存済みの完走行は22、基準と候補の両側の監査まで完了した組は3 shard・6条件。途中の好成績を採用根拠に数えず、登録を完走扱いへ書き替えない。使用した31701〜31708は新しい確認用seedから除外する。

一手の目的評価を毎回行う簡略案も32実行で調べたが、資源準備を理解できず不採用。未来を一手目的評価に置き換える8実行も得失が混在した。読みの頻度と、未来の本人が実行できる手段を別に扱う必要がある。

## 同一局面からの原因確認

戦闘steady、seed 43、未知傾向の保存済み本人を固定した。tick 1では弾薬3にもかかわらず旧継続が再補充を選ぶ。予測用乱数を701群・1701群・2701群に替えても同じ選択だった。条件付き平均の追加は3群とも防御へ変えた。一方、tick 16の余分な補充は3群とも平均補正だけでは残る。少数標本の偶然だけに原因を限定しない。

立て直しを加えた局面試験では未来の目的見積りと選択が変わったが、この局面試験だけを長期改善とは数えない。以下の固定長期比較と独立確認で採否を決める。

開発run 38994511431の競りgrowthだけが3時間のjob上限に達した。4実行のうち3実行の完走記録を回収し、1実行（未知傾向・立て直しあり）が未完了だった。元の登録・部分記録・取消状態を保全し、元の凍結ソースと同じPython/NumPyで不足した実行だけを取り直す。完了済みの行を得点で選び直さず、結合後に元の登録全体を監査する。これは前述の性能退行による317xx確認の中止とは別の、実行時間上限への対処である。

待ち時間を直列に増やさないため、候補のコードと係数を固定し、未使用の乱数群による確認をこの補完と並行して開始する登録にした。開始時点は28実行の監査済み・3実行の完走記録・1実行の未完了である。**採用には元の開発全32実行と独立比較の完了を引き続き要求する**。事前登録は `confirmation_plan.json`、補完の由来は完成データの `completion_provenance.json` に残す。

確認結果を一件も取得する前に、従来CLIの既定である8手間隔も対照へ追加登録した。当初の7手間隔の登録は維持し、同じ候補実行に対して二種類の世界予測・7/8手間隔を比較する。追加は旧方式の224主実行・16ストレス実行で、新しい独立標本や新候補とは数えない。`periodic_eight_plan.json` に開始前の条件と理由を固定した。

競りsteadyの変化条件では、新候補0.229736に対し区間予測・間隔7は0.265137だった。この一例は隠さない。一方、同じ実経路の各状態で完全情報の目的参照との差を合計すると、新候補0.047578、既存0.050348となり、実現得点の大小とは逆になる。状態と結果の偶然性を含む一経路の得点だけで、一般的な判断能力の退行と断定しない。新しい乱数群の独立比較を必要とする理由である。

同じ根元から実応答列を使った8窓の事後再生では、新候補の未知傾向は実際の再計画による目的寄与が平均+0.001404、変化条件は−0.002533。有限な二手の未来制御と実際の長い再計画の差は消えていない。`owner_recovery_auction_steady_bellman.json` と `owner_recovery_auction_steady_replay.json` に保存する。

終局が近い局面だけで改善した可能性も分ける。現時点で監査済みの14開発条件について、最後の予測窓16手へ入る前のtick 112で、戦闘・資源管理・賭けの12条件すべてが区間予測・間隔7より高い目的点だった。競りsteadyの未知傾向は+0.037598、変化条件は−0.028564で、競りの悪化も終盤だけの現象ではない。これは実経路の事後診断であり、無期限の世界への保証や学習効果だけの因果推定ではない。`owner_continuity_development_phases.json` は各傾向区間の前半・後半も保持し、区間開始までの資源差を持ち越した結果として扱う。

## 人格による差を実行の不備と混同しない

資源管理の開発例では、growthは128手で設備投資をせず、steadyは未知傾向で3回、変化条件で4回投資した。固定軸の不変だけでなく、行動の差も残る。ただし各人格は異なる状態へ進んでおり、頻度の差だけを心理的な妥当性とは扱わない。

growth・未知傾向のtick 64を保存済み本人から再評価した。投資は目的平均0.119034、選んだ収穫は0.117418で、**将来の目的利益を高く見積もっている投資を、本人の選好が退けていた**。全候補の評価前に投資を落としていたわけではない。この人格の時間割引は0.7725で、割引後の主義効果は投資−0.211783、収穫+0.578272。既存の主義の許容幅を外れる。成長の重視と、先の利益まで待てる傾向はこの設計では別物である。

これは一局面のモデル内の切り分けであって、その将来予測が正しい証明や、人格の設計が人間として妥当な証明ではない。目的得点差をすべて判断ミスにして人格係数を調整することはしない。`owner_resource_preference_diagnostic.json` に選択前の全候補評価を保存する。

独立確認から最初に完走した資源管理seed 41102・egoの傾向変化条件では、区間予測・間隔7より目的点が0.036458低かった。両者の応答予測は同一だが、最後の設備投資が旧方式のtick 35に対し新構成では98になった。tick 64の保存状態を読み直すと、16手評価では投資の目的平均が選択した収穫より0.001804低い。同じ人格・ルール・コアのまま、診断だけで32手に伸ばすと投資が0.011677高く、64手では0.040292高くなり、どちらも投資を選んだ。**この例を人格による正当な損だけに分類しない。有限な評価範囲による取りこぼしも含む。** `resource_ego_41102_roots.json`、`resource_ego_41102_tail31.json`、`resource_ego_41102_tail63.json` は実行前状態の事後診断であり、伸ばした方式の長期実行成績ではない。登録済みの確認候補は変更していない。

## 何を検査するか

物理遷移と公開応答の乱数再生、実際の一手をモデル内の本人へ適用した後の全状態一致、固定人格の不変、保存復元後の選択・結果更新を検査する。予測開始後に実本人が変わった古い予測器の再利用は拒否する。

予測と実行の差については、同じ根元の一手から、宣言した未来の判断器を実際に観測された応答列で再実行する。これにより、目的の差を「世界・標本の残差」と「その後の実本人の再計画の寄与」に分ける。この診断が成立するのは今回の**応答確率が自分の手に依存しない**検証世界だからで、反応的な相手に観測列を使い回してよいわけではない。経路の嗜好も開始時点の同じ本人で採点するが、事後の実現効用であり期待効用の保証ではない。

Linuxの実観測更新をWindowsで再計算した際、保存した損失差に5.55e−17の差が出た一例がある。許容誤差で全状態一致を装わず、事後の継続診断は共通の根元を通過した**実際の保存済み本人**から始める。元のプラットフォームでの厳密な監査と、別環境での事後診断を区別する。

長い実行の時間上限への備えとして、実行管理側に保存・再開を追加した。判断コアは変更せず、世界・解決済みの本人全体・実世界の乱数・経路を保持する。変更前に取得した4ルール2方式と26手の復元境界を含む計9実行について、変更後の通し実行と、各区間を別Pythonプロセスで再開した実行は、計測時間以外の全項目が一致した。`owner_checkpoint_equivalence/verification.json` はこの運用上の一致検査であり、追加の知能品質の標本には数えない。既に実行中の確認群は元の凍結ソースで継続している。

## 採った考え方と限界

[Bertsekasのrollout / MPCの整理](https://web.mit.edu/dimitrib/www/ADP-MPC.pdf)を参照し、継続方策の価値を使う評価と、実際にいつ改善方策を実行するかを分けた。本実装の人格による選択、有限標本、途中評価、誤った世界モデルに、単一目的の方策改善保証をそのまま適用しない。

今回もゲーム側が合法手・公開状態・条件付き遷移・目的の意味を与える。未知のルールの発見、人間相手への強さ、住人としての面白さ、全ジャンルの一般化をこの検証で達成したとは扱わない。

費用の診断として、保存した戦闘steady・未知傾向・tick 64を、現行コードと予測seed 701〜703で一度測った。ローカルCPUで48.405秒、想像内の短い再計画は103回、選択は `strike:2`。プロファイラーなしの一局面の実測であり、全局面の平均・クラウドの所要時間・大量NPC性能ではない。今回の品質候補は毎回重く読むため、通常の高速反射と同等の費用とは扱わない。
