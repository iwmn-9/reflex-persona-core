# 学ぶ本人の継続と長期判断

**判定：学ぶ本人と未来の立て直しを接続した `receding_recovery` を、品質を優先する任意構成として採用する。**

開発96実行、独立確認560実行、長期ストレス40実行を完了した。確認群では競り・資源管理・戦闘・賭けのすべてで、4対照に対する平均目的得点が改善した。競りは8世界seedのそれぞれの平均でも改善した。性格・主義・ゲームのルールを変えず、学習後の本人から再計画し、予測中の本人にも必要な短い立て直しを認めた構成である。

全人格の全条件で損をなくしたわけではない。人物と傾向条件を組み合わせると平均悪化が4群残り、有限な先読みで設備投資を見落とす例も確認した。これらを明示したうえでの採用であり、全ゲームの既定値、人間水準、低費用な大量NPC実行の認定ではない。

## 変更した仕組み

将来を評価する本人と、実際に動いて学ぶ本人を、同じ `DecisionLoop` の更新へ接続した。`RecedingOwner` は実観測を解決するたびに更新済みの本人から予測を作り直す。未解決の試行のまま次へ進むことや、不完全な予測を暗黙に即時判断へ置き換えることは拒否する。

毎回読み直すだけでは、戦闘の成績が悪化した。未来の本人が即時判断に限られていると、弾薬を使い切った後に立て直せない未来を見積もり、現在の本人が補充を過大評価する場合があった。今回の任意構成では、**予測中の合法手のどれにも正の即時目的利益を見込めないとき、更新済みの同じ本人で二手の分岐評価をする**。準備から実行へ戻る能力を、未来の評価側にも持たせる。

固定構成は `world_model='posterior'`、`purpose_estimator='conditional'`、`tail_recovery=2`、未来15手、予測seed 701〜703、実判断ごとの再計画。追加の短い計画は各経路で最大16回。条件付き平均は目的点の推定に使い、標本経路の損失・嗜好・学習イベントを平均へ置き換えない。未来の全時点で外側と同じ長い探索を再帰実行する仕組みではない。

性格・価値観・Policy係数・ゲームの公開ルール・目的定義は固定した。全ゲームに同じ構成を使い、入札・補充などの行動名やゲーム名によるコア分岐は追加していない。`reflex/core.py` と `tools/continuing_games.py` は開始時の main（`da4d862`）と同一。接続と既定値は [OWNED_VALUE](../../docs/OWNED_VALUE.md) を正本とする。

目的点が落ちた理由を一括して人格へ帰属させない。同じ根元の本人を保存し、候補全体の採点と、予測後に実際に進んだ経路を照合する。

資源egoの16手評価は、予測乱数1701/2701群でも投資を退けた。一つの標本群だけの偶然とは扱わない。一方、先読みを伸ばした診断は新方式の長期実行成績ではなく、登録した候補をその場で置き換える根拠にはしない。保存局面の評価も、予測が正しいことや人間としての心理的妥当性を証明しない。

予測と実行の差は、同じ根元・同じ最初の一手から、宣言した未来の本人を実応答列で再生して調べる。目的の差を「世界・標本の残差」と「実本人の再計画による寄与」へ分ける。今回の応答確率は自分の手に依存しないため成立する診断であり、反応的な相手に実応答列を使い回せるとはしない。

さらに144区間で、実経路と参照経路を元の本人の候補集合へ同時に入れ、最優先価値の許容範囲・目的の許容幅・スカラー採点まで比較した。競りsteady・seed 41104/41108・変化条件の各8区間では、目的点が落ちた計8区間すべてで、本人の完全な選択手順も参照経路を選んだ。一方、戦闘growthのtick 128では、実経路の目的点が0.001953低くても最優先価値の候補集合には実経路だけが残った。tick 208では目的点が0.004232高くても参照経路だけが残った。

この事後の単一経路比較は、意思決定時の期待値・リスクや意図的な犠牲の証明ではない。経路を単独で採点した `realized_persona_gain` は候補間の最優先価値の許容範囲を含まないため、人格選好全体の優劣とは区別する。別名への置換、同一経路の同点、保存済み本人と結果の一致、本人を変更しないことも検査した。

競りには、検証側だけが真の有限期間Bellman価値を使う収支分解も用意した：

**最終得点 ＝ 初期の完全情報価値 − 訪問状態での目的機会損失の合計 ＋ 条件付き平均ゼロの残差**

残差を除いた値は、固定方策を同じルールの新しい乱数で繰り返す場合の目的収益の不偏推定量になる。ただし分散が必ず小さくなるとは限らず、少数seedから優劣を保証もしない。完全情報の参照には、本人に知れない将来変化や人格としての支払いも含む。コアへ真値を渡さず、**登録した実得点の基準をこの事後指標へ置き換えない**。

## 得たもの、費用、適用限界

- **得たもの**：実観測後の学習・欲求・進展を次の長期評価へ戻し、未来の本人にも有限の立て直しを認める接続。4つの異なるルールで同じ構成の長期目的得点が改善した。
- **取り除いた近似とその費用**：未来の本人を常に即時判断だけに制限する近似を一部外した。その分、現在の毎回の再計画と想像内の短い探索が必要になった。安い方式と同等の計算量での改善ではない。
- **残したもの**：固定人格・主義、学習と欲求の更新、ゲーム側の公開ルール、通常の高速反射。全員を目的点だけで選ぶ人格へ置き換えていない。
- **残る急所**：評価窓より遅い投資利益、世界モデルと有限標本の誤り、反応的な相手を含む実ゲームへの接続。人格と傾向の組合せには損も残るため、一律の標準昇格はしない。

採用は、登録した競りの独立seedでの改善と、他ゲーム・人格の全確認、負の群の原因調査を満たした任意構成としてのもの。単に予測誤差を下げたり、部品テストが通ったことだけを採用理由にしない。判定と全入力の一覧は `owner_continuity_acceptance.json`、出所の一覧は `evidence_index.json`。

今回の品質比較では毎回重く読む。保存した戦闘steady・未知傾向・tick 64の一局面では、ローカルCPUで48.405秒、想像内の短い再計画103回、選択は `strike:2` だった。プロファイラーなしの単発実測で、全局面の平均や大量NPC性能ではない。同じ計算量での優位性も示していない。通常の高速な反射Policyは変更していない。

ゲーム側が合法手・公開状態・条件付き遷移・目的の意味を与える。未知のルールの発見、行動に反応する相手へのこの診断の一般化、無期限の世界、人間相手への強さ、住人としての面白さは、この4種類の検証で達成したとは扱わない。固定軸の不変と行動頻度の違いも、人間の人格を再現した証明ではない。

## 研究との関係と再現

[Bertsekasのrollout / MPCの整理](https://web.mit.edu/dimitrib/www/ADP-MPC.pdf)を参照し、継続方策の評価と、実際に改善した選択をいつ行うかを分けた。人格の多目的採点、不完全な世界モデル、有限標本、途中評価を持つ本構成へ、単一目的の方策改善保証をそのまま適用しない。

有限な評価範囲の取りこぼしについて、[STEVE](https://papers.neurips.cc/paper/8044-sample-efficient-reinforcement-learning-with-stochastic-ensemble-value-expansion.pdf)、[Adaptive Lookahead](https://arxiv.org/abs/2201.12403)、[長い価値展開の限界](https://arxiv.org/abs/2303.03955)、[parallel rollout](https://engineering.purdue.edu/~givan/papers/deds01.pdf)も調べた。深さや複数の継続方策を比較する考え方は候補になるが、共通の評価バイアス、将来の本人の選好、情報を知らない時点での方策選択を揃える必要がある。これらの学習器や保証を実装したとはしない。登録した比較へ途中から別方策を足していない。

公開する記録は `evidence_index.json` を入口とする。各研究の登録・元の監査・実行列・凍結ソースを対応づけ、未完了・中止記録は比較対象から分ける。`source_snapshots.zip` は元の各実行ソース、`final_source.zip` は今回の実装と解析用コード。大きいJSON/JSONLはgzipで保持する。展開時はindexの元ファイル名と論理ディレクトリを使う。

`analysis--*.py` は解析コードの閲覧用の写し。`final_source.zip` を展開すると `results/*.py` に元の配置が戻り、共通モジュールを参照できる。`orchestration--*.py` は全登録の照合に使ったローカル補助コードで、workspace固有の経路定義を含む。固定比較の原本は各registration、workflow記録、監査結果から追える。数値実装の回帰検査は `python -m unittest discover -s tests -v` で行う。
