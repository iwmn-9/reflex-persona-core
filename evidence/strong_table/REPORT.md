# 一人の目的特化CPUに、三人の人格NPCはどう対応したか

## 結論と構成

勝利だけを狙う高予算CPU一人と、固定人格を持つ三人を同じ卓へ接続した。三人は全員、それぞれの公開観測から強敵と他のNPCを学習する。強敵自身も三人を学習する。特定の一人だけを改善する以前の試験から、実際に相互対応する卓へ変更した。

「知能へ極振り」は、人格の副次利益を除き、ゲーム目標と探索へ予算を振る構成として実装した。最適CPU、解かれたゲーム、知能上限の達成を意味しない。主試験と二つの対応比較で計1,408試合を実行した（開発中の予備試験はこの数に含めない）。反射NPC相手には約8割の勝利持分を取るが、計画・学習する相手との対戦で、その強さの限界も測る。

候補は、同時入札と有限の手札配分を見るGoofspiel型、拒否費用・資源枯渇・連番の利益を見るNo Thanks!。前者は13枚・最高同額は賞品破棄・賞品のシャッフル順を最初から全員へ公開する検証用拡張。OpenSpielの未知ランダム順や、市販「ハゲタカのえじき」の負札・持越しを再現したものではない。後者は3〜35から9枚を除いた24枚、4人各11チップ、連番の最小札のみ失点・チップは失点軽減という基本ルール。未知の除外札と未来山札は渡さない。GUIは使わない。二段階投資・売却を見るFor Saleも次の候補だが、この報告では実装・実行していない。

## 先に固定した主試験

16の独立した系列、各12回の再対戦、三人の方式3種、2ゲームで**1,152試合**。人格・強敵席・欠ける人格を均等に回し、方式間の賞品順・山札を合わせた。同じ系列の12回は記憶がつながるので、1,152個の独立標本とは数えない。

|三人の方式|Goofspiel型：強敵の勝利持分|No Thanks!：強敵の勝利持分|
|---|---:|---:|
|反射のみ|153/192 = 79.7%|162.5/192 = 84.6%|
|計画、相手仮説は固定|171/192 = 89.1%|56/192 = 29.2%|
|計画＋公開行動から継続学習|45/192 = 23.4%|57/192 = 29.7%|

持分は同点優勝を人数で割った値。低いほど三人側が優勝できている。三人の協力や結託を台本で与えてはいない。

入札では、学習追加による三人合計持分の差は計画のみより+65.6ポイント。16系列を単位とする対応付きブートストラップの95%区間は+58.6〜+72.1ポイント。192対応中、三人の持分が改善131・同じ58・悪化3。同額最高入札へのNPC参加回数は計画のみ1,198→学習あり1,073。反射のみの1,966よりも減った。

No Thanks!は反射から計画へ進める効果が大きい。チップ切れによるNPCの強制受領は260→6→8。ただし学習を計画へ追加した持分の差は−0.5ポイント、95%区間−8.9〜+7.8ポイント。改善46・同じ101・悪化45で、上積みがあるとは判断できない。学習が一律に有効という結論は捨てる。

三人側は入札4,113手、No Thanks!2,119手で、同じ実盤面・同じ人格状態・同じ探索乱数の固定仮説版と違う手を選んだ。これは反応した量で、全てが有益な読みだったことの証拠にはしない。比較は三人の読み・判断と全員の対応が重なった効果で、個人学習の単独効果ではない。

事前条件は [analysis_preregister.json](analysis_preregister.json)。主試験の実装は `93e35b03ced1797467c9693ef3215ca60f62a12f`。方式ごとの出力を統合したmanifestは試験後生成で、試験前の分析条件のSHAを参照する。都合のよい系列へ入れ替えていない。

## 何を組み合わせ、何を省いたか

通常の共通finite Policy、目的の許容幅、公開行動の有限仮説、終局までの探索を接続した。性格と主義は書き換えない。入札は全標本に共通する本人の札配分をエリート保持・置換で探し、新しい相手標本で検証する。No Thanks!は根のTAKE/PASSと8種の本人の閾値継続を訓練標本で比較し、選んだ継続を新しい山札標本で検証する。実際には一手だけ実行して全員が再判断する。

強敵は訓練128・検証256標本、入札192計画×5世代。NPCは32・96標本、64計画×3世代。最後の一枚などでは探索が早期終了するため、積は名目上の予算で実演算数ではない。

共通の `choose_with_goal` は、モデル内で明らかに目的を犠牲にする手を候補から外し、残りを本人の既存の人格採点へ返す。許容幅0.12、共通標本の差の標準誤差2倍を用いる。実勝率を12ポイント以内へ保証するものではなく、将来モデルの誤りも覆わない。大きな目的犠牲を伴う主義の自由は狭まる。競争で得したことを親切や裏切りへ直結させる効果は省き、本人の価値観の数値は残した。

相手仮説は一様・札/資源への単純方策6種、既存人格方策4種、直近傾向と条件付き予測2種。実際の相手の人格・内部記憶・制御方式は入力しない。ただし評価対象の人格群と仮説群は同じ4種類を含むため、未知人格群への汎化試験ではない。No Thanks!の人格仮説は既存Policyと一致する数値カーネルで動かし、別の心理式を手書きしない。64状態と履歴・終盤を含む3,000状態で一致を検査した。

心理軸・復讐ボーナス・対策自体の報酬・勝率均等化は追加していない。各個体は独立した有限記憶を持ち、公開された実行だけから学ぶ。未来シミュレーションから学習しない。三人の記憶を共有した連携はない。

## 人物として何が見えたか

代表例は最初の固定系列seed6100から抽出した。全体の比率は上記の全試験で判断し、以下の一手を性能の証明にはしない。元の数値は [cases.json](cases.json)。

- 協調型careは3回目の入札対戦、12点賞品で固定仮説なら2札だったところを12札へ変更。他の実入札10・8・11を上回り獲得し、その試合も26点で優勝した。協調型だから常に譲るのでなく、自分が取りにいく意味のある場面では踏み込めた。
- 成長型growthは初対戦、3点賞品へ4札の代わりに7札を出して獲得。ただし終局は3点で最下位、強敵21点だった。直後の局面では1札を選び、札を温存した。局所の取り合いと温存はできても、7札投入を正しい長期判断だったとは言えない。モデル上はその手の優勝見込み77.1%で、楽観が目立つ。
- No Thanks!のcareは4を持つ局面で3を受領し、連番の失点を1減らした。固定仮説版はPASS。現在のモデル内の優勝持分は両方29.2%だが、TAKEの平均失点は少ない。受領・拒否を固定した性格ではなく、同じ目的の中で手段を変え、その対戦は52点で優勝した。
- 自己主張型egoはチップ1枚、18札・pot0で受領。モデルの優勝持分は両候補0、平均失点はTAKE90.5/PASS85.3なのにTAKEを選び、最終77点で敗北した。資源不安に反応する一方、勝利見込みが全候補0へ潰れた時の判断は弱い。これは面白いエゴとして無条件に正当化しない。

固定人格が残っていることは検査した。修正後64試合での同一contextの比較では、入札1,248判断中902、No Thanks!2,606判断中365で人格による選択差があった。同じ実contextの固定軸だけを四人格へ差し替える選択比較も行った。人物ごとの勝利持分や行動の差を、全員の勝率を揃えて消してはいない。一方、好意・関係修復・長期の生活や、遊んで面白いという体験はこの競争卓では測れていない。開発側の観測では、勝利のために手段を変える芽はあるが、こだわりの読みやすさと長期合理性は完成していない。

## 強敵の探索量だけを増やした比較

別の4系列×8回×2ゲームについて、通常と増量の各64試合、計128試合を実行。NPC側の予算は固定。Goofspiel型は訓練256・検証512・768計画×10世代で、計画×訓練標本×世代の名目予算16倍、検証2倍。No Thanks!は訓練/検証2倍で、継続の種類は同じ8種。

強敵の持分は入札7.5→7.0/32、No Thanks!12→10.5/32。対応差の95%区間はいずれも0をまたぐ。強さの増加を確認できず、計算量を増やせば完成するという見立ては捨てる。三人の対応はこの増量条件でも残ったが、最適CPUに対抗できたという証明ではない。4系列という小さい比較の限界もある。[条件](budget_analysis_preregister.json)、[対応集計](budget_comparison.json)。実装は `8d1b0e5`。

## 接続の修正と再対戦

忘却の判定に用いる予測が、実際の計画に用いた予測と違っていた。主試験の入札では、強制手を除く41,472学習記録全てで差があり、実予測に対して必要だった驚きによる旧証拠の減衰を1,135回見逃し、余計な減衰を37回起こした。科学的な変化検出器ではなく、既存の「一様の半分未満なら旧証拠を弱める」規則に照らした診断。[記録](feedback_diagnostic.json)。

`HypothesisTracker.observe(..., forecast=...)` に実際の更新前予測を渡し、予測損失と忘却の基準を揃えた。無指定の旧経路は互換。No Thanks!では直近の受領・拒否から覚えた閾値が根の仮説だけに入り、未来では0へ戻っていた。共通の閾値を両方へ接続した。人格軸は増やしていない。修正後の実対戦14,688件の非強制学習では、予測と忘却の食い違い0・必要な減衰の見逃し0・余計な減衰0を確認した。

修正前 `8d1b0e5` と修正後 `fa28678` を別の4系列×8回×2ゲーム、各64試合で比較。強敵とNPCの双方へ同じ修正を入れた。事前条件は [feedback_analysis_preregister.json](feedback_analysis_preregister.json)。

修正後、強敵の持分は入札7→3.5/32、No Thanks!10→9.5/32。三人側の対応差は入札+10.9ポイント（95%区間−6.3〜+26.6）、No Thanks!+1.6ポイント（−7.8〜+9.4）。いずれも4系列では明確な性能向上を確定できない。入札は三人側で改善7・同じ21・悪化4、No Thanks!は6・20・6。接続契約の修正は残すが、勝率改善の保証とは扱わない。二つの修正を一緒に適用した比較なので、それぞれの単独寄与は未測定。[対応結果](feedback_comparison.json)。主試験の1,152試合を修正後の実装の成績として流用しない。

## 残る急所と採用の範囲

各試合で本人が最初に決定した時のモデル予測と最終実持分を比べると、入札の学習NPCは70.6%→25.5%、強敵は79.6%→23.4%。No Thanks!はNPC44.5%→23.4%、強敵45.3%→29.7%。計画のみの入札NPCは78.2%→3.6%で特に楽観的だった。予定した共有継続と実際の毎手の再判断が違うため、これは同じ予測対象についての厳密な校正検定ではない。しかし将来モデルを現実の確率として扱うべきでないことは分かる。[診断](forecast_diagnostic.json)。

No Thanks!の相手の次の手は一様よりよく予測しているのに、学習追加の持分は改善していない。「相手を読めた」と「読みを本人の長期利益に変えられた」は別。Goofspiel型の人格仮説は将来の札順位で外挿し、No Thanks!の未来の人格仮説は即時Policyを使う。実際の先読みNPCの再計画、相手の次の学習、本人の将来の人格採点を再現したものではない。新しい心理要素より、これらの継続近似の改善が優先になる。No Thanks!の学習NPCでも、選べる手が二つある16,252判断中1,412では全候補の標本優勝持分が0だった。先の自己主張型の例のように、目的尺度が潰れた局面で副次利益が素点悪化を選ぶ弱さは残る。

取得したものは、一人の強敵に三人が別々に対応する反復卓、目的を守った人格選択、実予測と忘却の接続、ゲームをまたぐ検証条件。捨てたものは、本人の未来を一様な行動だけで代用する方法、未来の人格に別の手書き式を使う方法、学習や探索量だけで賢さが成立するという見立て。残る代償は計算費用、モデル内目的制約による大きな自己犠牲の自由の縮小、仮説群への依存。

共通の人格Policyと目標許容幅はゲーム名を持たない。ルール遷移・合法手・公知情報・勝利成果の定義・探索の継続モデルはゲーム側へ置く。二つの異なるゲームへ同じ境界を接続したが、未知のゲームの正しい評価を自動で獲得する仕組みではない。通常の高速反射、他の戦闘・社会・複合勝利接続の既定は切り替えない。新経路は研究構成として残す。

## 検査と再現

主試験全1,152試合について、独立したリスト/台帳による73,010実遷移・65,522チップ台帳の照合、95,474実判断、72,391人格選択、142,186公開学習記録を検査した。目的CPUはモデルの優勝持分最大、同点時のみ素点を用いた選択と全件一致。人格・主義の固定、三人の記憶分離、方式間の実賞品順・山札一致を確認した。[主監査](audit.json)。

主試験の72試合（最初の系列、両ゲーム、全方式、全12回）では探索を含め全手を再生成して一致。増量CPU条件と修正版各16試合を加え、探索の完全再生は計104試合。その他は全ルール・人格選択・公開学習を照合したが、探索全体を再実行したわけではない。学習照合は同じ学習器の再生で、推論品質の独立証明ではない。追加256試合も全ルール・人格・記憶を照合済み。[追加監査](additional_audits.json)。

全体検査は671件、657成功・任意の麻雀14skip。NumPy以外の実行時依存は増やしていない。ローカルCPUのみ、Colab・Google Drive・GPU・LLMの新規実行はない。主試験の最長workerは約44.6分、4分割で同時実行した。worker時間の和を実経過時間とは数えない。巨大な実軌跡はローカル保存し、公開するのは集計・条件・監査・小さい実行例のみ。

現行修正版で新規試験を行う例：

```sh
python -m reflex.strong_table --root FRESH_ROOT --start 6500 --seeds 16 --encounters 12
python tools/audit_strong_table.py --root FRESH_ROOT --replay
```

保存した主試験の数値を再現する場合は、復元可能な別checkoutで `93e35b03ced1797467c9693ef3215ca60f62a12f` のソースを使い、seed6100〜6115・12回・3方式・2ゲームを実行する。同revisionの `strong_table` CLIで `--start 6100 --seeds 16 --encounters 12` を指定する。試験後の表示修正を含む現行ソースを、旧試験の実装として扱わない。各試験は104ソースのSHAを実行前に登録している。監査は必要な旧モジュールだけを固定commitから読み直し、登録SHAとの一致を確認する。[実装の対応](implementation.json)。
