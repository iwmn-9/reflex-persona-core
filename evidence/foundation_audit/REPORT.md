# 全体診断：人格を維持する接続と、賢さを測る基準

## 結論と採否

最終目標は、異なるゲームでも「その人物なりに合理的で、対戦相手や住人として面白い」NPCの土台。現在の人格・目的・予測・実行を分ける構造は維持する。全面再構築や心理分類の追加を正当化する根拠は得ていない。一方、任意部品の追加と検査数の増加だけでは、全般的な賢さの安定へ進めているとはいえない。

今回は先に比較の基準を組み直した。既存の反射、人格付き4手先読み、同じ予測から当手の目的点を優先する比較役、8手先読みを、同じ開始条件で通し実行した。さらに小さな公開ルールでは、全分岐を計算して現在の制御器の達成確率と目的だけの最善値を分けた。

採用した改修は二つの接続修正。人格・主義の係数、勝敗の補正、ゲーム名による分岐は追加していない。4手から8手への一律変更、目的優先への置換、新たな学習器の標準化は採用しない。全般的な賢さ、人間水準、面白さの完成は未達。

現在の目標・不足・改修順位の正本は [PROJECT_DIRECTION](../../docs/PROJECT_DIRECTION.md)。以下は今回の実証と採否の根拠。

## 何を得て、何を捨てたか

| 判断 | 得たもの | 捨てたもの・負担 |
| --- | --- | --- |
| 判断をやり直す際も関係評価を維持 | 停滞解除の案が成立せず元へ戻る場合も、同じ人物として選ぶ。無関係な同時処理NPCも保護 | 関係を抜かした簡略な再採点。新しい心理パラメータは不要 |
| 無駄な費用の除外に関係上の利益も含める | 少し費用が高くても、本人にとって大切な相手を助ける候補を残す | 「物理効果が同じなら安い方だけでよい」という過剰な省略。一部の候補が残り、比較量は増えうる |
| 全体比較と全分岐評価を追加 | 意図した人格の支払い、予測の不足、偶然の勝敗を分けて調べる基準 | 異なるゲームの得点を一つの勝率へまとめる評価、反復数だけによる強さの主張 |
| 大枠を維持し、先読みの標準設定を変えない | 個性と既定の反射挙動を保ち、改修先を目的評価・継続予測へ絞る | 「長く読む」「目的点を優先する」だけで普遍的に賢くなるという仮説 |

## 修正した実不具合

### 1. 停滞解除を断念すると、相手への態度が抜ける

改善の証拠を求める `ProgressWatch` が候補を制限し、十分な代案が得られない場合、元の候補から基準判断を再計算する。その再計算へ `SocialMemory` の関係評価が渡っていなかった。同じバッチの、停滞監視を使っていない別NPCの基準判断にも影響した。

`DecisionLoop` の通常選択と復帰先に同じ関係評価を渡した。信頼を失った相手に対し、復帰時だけ理由なく好意的になる挙動を防ぐ。実行主体を複製した予測と保存復元でも同じ判断になることを検査した。旧版へ最終の再現検査を適用すると13の失敗が出る。これは検査条件の失敗数で、13件の独立したゲーム被害を意味しない。

### 2. 同じ物理効果なら、相手が違っても高い費用を無駄扱いする

`avoid_waste` は、確定した利益が同じなら高い費用の候補を削る。しかし関係上の価値を比較に含めていなかった。例えば同じ量を与える二択でも、信頼する相手を助ける価値が本人にある場合は同じ利益ではない。

任意の `appraisal` を比較へ加え、関係評価も同じ場合だけ費用による除外を認めた。通常、停滞からの復帰、相手読み、計画補完、学習した提案との比較に接続した。高い方を強制的に選ぶ変更ではない。既存Policyが費用と人格を採点する。違法手・既知の失敗は関係評価が高くても復活しない。

主な変更は [decision_loop.py](../../reflex/decision_loop.py)、[judgment.py](../../reflex/judgment.py)、[root_completion.py](../../reflex/root_completion.py)、[paired_guard.py](../../reflex/paired_guard.py)。契約は [DECISION_LOOP](../../docs/DECISION_LOOP.md)。

## 通し比較の条件

| 群 | 実行数 | 判断数 | 条件 |
| --- | ---: | ---: | --- |
| 開発 | 256 | 2,800 | 8ゲーム系統 × 4人格 × 2実行seed × 4方式 |
| 確認 | 512 | 5,302 | 8系統 × 4人格 × 4実行seed × 4方式。人数等を変え、合法な3行動の導入後から開始 |
| 公開グラフ | 1,024 | 8,704 | 8ルールseed × 長さ5/12 × 4人格 × 4実行seed × 4方式 |
| 合計 | 1,792 | 16,806 | 全登録ジョブ完了、エラー0、全実遷移の再生一致 |

各方式は同一の人格・開始盤面・実世界seedで対応づけた。確認の導入手は制御器の評価結果から選ばず、各方式・人格で同じ物理履歴を使う。導入手を本人が学習した経験として捏造しない。開始時に既に終局していた実行は0件。配布用の16実行のパイロットは主比較へ加えていない。

- **reflex**：追加先読みなし。ゲーム側が与える即時の効果表現には既存の近似評価が含まれるため、無知なランダムCPUではない。
- **persona4**：共通の4手先読み。モデルseedは401–404の4本、個人の固執度は0.5。
- **purpose4**：同じ予測と未来の人格反射を使い、当手だけ目的点最大を優先。同点ならpersona4を維持する。全未来から人格を除いたCPUでも、最善CPUでもない。
- **persona8**：同じ4本のモデルで先読み上限を8手へ延長。
- **oracle**：公開グラフだけの目的最適比較器。公開された遷移確率を後ろ向きに計算し、将来の実抽選結果は参照しない。グラフ群ではpersona8の代わりに用いる。

この比較では即時の経験学習・関係記憶・停滞監視を有効化していない。予測方式を切り分ける診断であり、すべての部品を同時使用した品質の実証ではない。

## 確認512実行の結果

各欄は同一条件16組の **目的点が改善 / 低下 / 同じ**。異なるゲームの得点差を合算しない。引分けもゲームが宣言する終局値へ含む。これは今回の接続修正前後の勝率比較ではなく、既存の判断方式間の診断。

| ゲーム系統 | 4手先読み − 反射 | 8手先読み − 4手 | 目的優先 − 人格付き4手 |
| --- | ---: | ---: | ---: |
| オークション | 1 / 0 / 15 | 0 / 0 / 16 | 0 / 0 / 16 |
| 複数資源・勝利条件 | 3 / 0 / 13 | 0 / 0 / 16 | 0 / 0 / 16 |
| ギャンブル | 6 / 3 / 7 | 1 / 0 / 15 | 0 / 0 / 16 |
| Goofspiel | 4 / 1 / 11 | 0 / 0 / 16 | 0 / 0 / 16 |
| ハゲタカ型 | 2 / 0 / 14 | 0 / 0 / 16 | 0 / 0 / 16 |
| No Thanks型 | 6 / 0 / 10 | 0 / 1 / 15 | 0 / 1 / 15 |
| チーム戦闘 | 0 / 0 / 16 | 0 / 0 / 16 | 0 / 0 / 16 |
| チーム事業 | 5 / 0 / 11 | 0 / 1 / 15 | 1 / 3 / 12 |

4手先読みは有効な場面がある。ただし安定して反射以上ではない。8手への延長も、ギャンブルで1組改善し、No Thanks型とチーム事業で各1組悪化した。開発群でも、延長はオークションで2組、Goofspielで4組悪化している。長い先読みを標準化する根拠にならない。

目的優先でも、チーム事業は1改善・3低下、No Thanks型は1低下。モデルの目的点を高くすることと、実際の終局利益は一致しない。この結果だけで人格の偏りが優秀とも劣悪とも結論しない。選択後の軌道、未来の本人と相手、予測の打切りが変わるためである。

天井・重複も残る。ハゲタカ型と資源管理のpersona4は16件すべて成功、チーム戦闘は全方式16件すべて引分け。チーム戦闘の確認開始盤面は実質2種類で、他の7系統は各4種類。同じ物理軌跡も反復している。したがって1,792実行を1,792個の独立した問題と扱わない。全人格別の改善・低下、開始・軌跡の重複数、モデル枝が終局まで届いた割合は [summary.json](summary.json) に保存した。

失敗も [examples.json](examples.json) に残した。例えば確認No Thanks型のsteady、seed31101では、4手が勝利、8手が引分け、目的優先が敗北だった。事後に選んだ説明例であり、追加の独立試験ではない。

## 偶然の勝敗から離れた全分岐検証

グラフの標本実行を見た後、別のルールseed23108–23115を固定して追試した。各ルールは幅4、各手2候補、候補ごとに等確率の2遷移、終局の成功/失敗を持つ小さな公開環境。長さ5/12と4人格、3方式の計192方策を、到達可能な6,312個の本人状態で厳密に評価した。

実際にその制御器を毎手使う場合の全抽選分岐を計算する。記憶を含む本人の保存状態を計算の識別子に含め、単なる盤面だけへ潰さない。目的最適値を制御器へ渡さず、評価側でのみ参照する。各状態で「最適確率 − 現在の方策の確率」が期待累積機会損失と一致することも検査した。

| 残りの長さ | 反射 | 人格付き4手 | 同じ予測で目的優先 | 目的だけの最適値 |
| --- | ---: | ---: | ---: | ---: |
| 5 | 65.53% | 75.68% | 75.68% | 83.98% |
| 12 | 70.36% | 81.40% | 81.40% | 88.95% |

値は各条件の**公開モデル上の厳密な成功確率の平均**。192試合の観測勝率、人間との対戦勝率、現実のゲームへの保証ではない。人格付き4手と当手の目的優先は、64対応方策すべてで到達可能な全選択も同じだった。残る8.30 / 7.55ポイントの目的機会損失を、当手の人格的な妥協だけのせいにはできない。ただし目的優先でも未来の人格反射は残るので、人格の影響全体を除いた因果実験ではない。

今回のグラフでは、4本の終局成功/失敗標本により予測目的点の差が0、0.5、1.0、1.5、2.0に限られた。目的損を許す幅0.15より最小の正の刻みが大きく、当手の個性は目的点が同点の候補間でしか働けなかった。**許したはずの小さな妥協を、予測の分解能が表せていない。** これを個性が不要という証拠にしない。

説明例では、当手の予測目的点は二択とも0.5なのに、各手の後で目的最適に続けた場合の成功確率は62.5%と75%だった。両方の予測枝は終局まで届いているため、単に読みを伸ばせば解消する反例ではない。標本の粗さと未来の本人の弱い継続をさらに切り分ける必要がある。目的点と成功確率は別の尺度であり、この例の数値同士を直接減算しない。

## 検証とソースの対応

- 最終ソースの全972検査が成功。今回追加した11検査は、関係・復帰・費用除外の接続5件と、比較器・再生・全分岐評価6件。
- 通常の反射1,200判断の全レコードが基線と一致。学習を含む通常経路40エピソード・2,400判断も、計測時間を除いた全記録が一致した。
- 主比較と全分岐評価は、関係評価修正前に凍結したソースで実行した。その構成は関係記憶・停滞監視を使わない。修正後に16のグラフ全試合を再実行し、全判断・物理遷移等の記録が一致した。主比較の全実行が最終ソースと同一byteだったとは主張しない。
- 登録ジョブ、凍結ソースの全ハッシュ、実行ログのハッシュ、全実遷移のルール再生、保存復元を照合した。ルール再生は同じゲームエンジンによる整合検査であり、すべてが独立実装の審判という意味ではない。
- 旧版の復帰不具合と修正前の費用除外の失敗ログを保全した。既存の公開証拠を消して成功例へ置き換えていない。

基線は `3793112573113c99abdd761dcefb0b5ae4a4c2df`。[registration.json](registration.json) は実行前に固定した全条件、[provenance.json](provenance.json) は凍結ソースと追試の位置づけ、[controls.json](controls.json) は検査・同等性・修正後再生と最終ソースのハッシュ。完全な軌跡JSONLと凍結ソースは開発環境に保存し、公開側には全対応組の集計・条件・照合情報を載せる。

## 汎用性について残る限界

ゲーム名や個別の手に合わせた補正を共通コアへ加えていない。一方、ルール・合法手・目的・結果の意味・途中評価は人が実装したadapterから受け取る。「ルールだけ覚えれば未知ゲームでも同じ賢さ」は未達。

主比較の対戦相手は既存の宣言した方策。ハゲタカ型は7ラウンドの短縮条件。チーム系では比較対象の制御器は本人一人で、他の仲間は既存の参照方策を使う。全人格のチーム再交渉や最高知能CPUへの勝ち負けを今回新たに実証したものではない。関係修正による長期の面白さ・勝率向上も、この診断では測っていない。

Colab、GPU、LLM、Driveをこの作業で使用していない。ライセンスや新しい利用許諾も追加していない。

## 停滞の診断と次の改修

停滞していたのは「任意の読みや学習を増やせば、全体が順に賢くなる」という進め方。今回も読みの長さの追加だけでは改善と悪化が混在した。ここを人格別の係数調整で埋める方針は取らない。

次は **目的評価と未来の継続** を第一にする。全分岐比較で正解を得られる環境を参照に、途中評価、打切り、標本分解能、未来の本人・相手の方策を一つずつ分離する。予測が当たったかだけでなく、採った手が実際の目的と本人の価値にどう影響したかで判定する。

第二は **同じ本人としての一連の実行**。今回二つ直したが、改善の証拠を求める停滞監視と独立readerの併用はまだ未対応。予測を後で採点する機能も、遅延した成果から次の計画を改善する因果学習と同じではない。単に禁止条件を外したり、予測誤差を無差別に記憶させて接続完了としない。

その上で、譲歩・粘り・役割変更・立て直しが行動として伝わるかを調べる。心理軸の細密化より、少数の意味のある違いと、その人物なりの判断の一貫性を優先する。

## 再現

```sh
python -m pip install -e .

python tools/run_foundation_audit.py --root output/foundation-graphs --stage graphs --workers 4

```
