# 目的を分けた相手先読みの実対戦：衝突は減るが、勝利と停滞は悪化する

**既定への昇格はしない。** 新しい32条件・3方式・96実対戦では、`goal-uniform` の実移動失敗は対照4→1、留保6→0になった。しかし元方式に対して勝利は対照7→6、留保14→12へ減り、留保で1敗が生じ、未解決停止は31→74へ増えた。移動失敗の少なさを総合的な強さの証拠にしない。

この実装はdefault-offで利用できる有限の相手モデルであり、通常は従来の `TacticalControl(opponent_model='fixed')` を保つ。人格・価値階層・能力値・勝利条件・本人の実経験更新を変えて結果を取り繕わない。

## 前の予測試験とは別に固定した問い

[直前の56局予測試験](../goal_opponent/REPORT.md)では、目的多様性による移動先予測の改善があった一方、学習重みは移動先予測を悪化させ、全行動の対照条件も一様分布に負けた。あの不成立結果、source snapshot、design、preregister、評価hashは保存したままにした。

今回はそのgateを通過したと呼び替えず、**学習なしの等目的モデルを使う実対戦**を別に承認・事前固定した。対照・留保のすべての方式・seedを実行し、結果後の追加方式や調整はしない。改善した人格だけを採用対象に選別する評価でもない。

- 対照：enemy_convergence/bothとmixed_junction/both × 4人格 × 新seed2701/2702の両陣営 × 3方式、48局・16組
- 留保：open/secure/reference、choke/eliminate/switch、open/either/raider、choke/both/reference × 4人格 × 条件と人格で2701/2702を交互に配分 × 3方式、48局・16組
- 別枠の費用fixtureを4局。主効果の96局へ足さない
- 公開上の既知配置・相手方策族の新seedであり、未知環境への一般化ではない。tick/個体/同条件は相関する

[design.json](design.json)と[preregister.json](preregister.json)を2026-10-05 21:44:54 UTCに凍結。全方式でhorizon=6、samples=4、max_plans=24、recovery_plans=48、objective自己継続、root_completion=False、実行後だけの経験更新を固定した。

## 何を判断に接続したか

|方式|モデル|
|---|---|
|fixed|従来の目的戦術／攻撃的戦術の二つを交互に使う。既定|
|uniform-coverage|元仮説80%＋全敵の合法手独立一様20%を有限標本化する支持拡張対照|
|goal-uniform|公開の有効目的eliminate/secureを敵個体ごとに等重みにしたexpert積80%＋独立一様20%を有限標本化|

`goal-uniform` は前の予測部品と同じ公開 `tactical_scores`、softmax温度0.04、行動平滑化0.08を使う。**目的重みの学習は接続していない。**

各rolloutの広い一様枝と各敵の目的を公開rootからprivate hashで決め、6stepを通して保持する。達成済みになった目的だけ公開規則で切り替える。相手の実controller、実seed、未公開現在手は入力しない。新samplerの乱数は公開盤面・標本番号・深さ・相手IDから作る。実命中乱数とは別。現rootの自分の同時手で敵のroot手は変わらず、後続の自分の仮想手が解決した公開モデル状態には反応できる。

同じrootの全自己案とrecovery再評価で同じ潜在目的・action variateを使う。4標本は系統的な層化で、両目的が有効なら各敵の潜在目的はsecure/eliminateを2本ずつ含む。一様枝は0本か1本。各標本の目標周辺分布はprivate phaseに関して等目的・20%一様だが、**4標本は互いに独立でなく、全合法手・全共同組合せの支持を毎回保証しない**。任意の奇数samplesでは元の交互仮説の本数も不均衡になるため、等Fの解釈は今回の4標本に限定する。

これは以前の一step予測を未来の各状態で独立に混ぜる処理と同じ軌跡分布ではない。目的・一様枝が持続し、その選択自体が後のモデル状態を変える。また元Fに対して目的だけでなく行動分布のsoft化も違う。この試験が比較するのは**先読みモデル全体**であり、目的多様性一要素や前の予測精度が勝敗差を作ったと分離した実証ではない。

## 実際の移動と勝敗

移動失敗は解決後も元セルにいる実移動。敵だけ・味方だけ・両方を分離する。今回「両方」「原因未分類」は全方式0件。率は各方式が実際に選んだ移動数が分母であり、異なる後続軌跡を同じ入力の予測比較とは呼ばない。

|分割・方式|勝 / 敗 / 未決|全失敗 / 移動|敵だけの失敗|味方だけの失敗|
|---|---:|---:|---:|---:|
|対照 fixed|7 / 0 / 9|4 / 362 (1.105%)|4|0|
|対照 uniform-coverage|8 / 0 / 8|3 / 390 (0.769%)|1|2|
|対照 goal-uniform|6 / 0 / 10|1 / 392 (0.255%)|1|0|
|留保 fixed|14 / 0 / 2|6 / 348 (1.724%)|2|4|
|留保 uniform-coverage|10 / 1 / 5|25 / 440 (5.682%)|11|14|
|留保 goal-uniform|12 / 1 / 3|0 / 426 (0%)|0|0|

候補は移動を減らして失敗を隠したわけではない。全移動は対照362→392、留保348→426に増えた。ただし衝突機会自体も経路・戦闘の変化で変わるため、失敗差のすべてを「同じ危険を正しく回避した件数」とは呼ばない。

局等重みの全移動失敗率も対照1.188%→0.368%、留保2.235%→0%に減る。各方式すべての局で移動があり、分母0の局はない。支持を足しただけの対照は留保で大きく悪化しており、「多様にすればよい」でもない。

対照では両目的の平均進捗は高くなるが、ANDの完了勝利は減る。平均の部分進捗と、実際の全条件達成は別である。留保は両目的の平均進捗も低下し、未解決停止率3.944%→7.889%。最長stallが同じ7でも停止の総量は倍以上になる。

人格ごとの代表的な違い：

- 対照careは0→1勝、両目的の進捗も改善。対照growthは3→2勝、egoは2→1勝
- 留保steadyは3→4勝、停止22→11。一方careは4→3勝、停止0→34、eliminate平均0.84444→0.58808、secure平均1.0→0.77604
- 留保egoは4→2勝・1敗。choke/eliminate/switch/2701では元は勝利、候補は敗北。ここは目的が一つなので、悪化を目的推定の誤りだけに帰せない
- choke/both/care2702では味方移動失敗2件が消えても、元の勝利を失い、停止が34件増える。逆にchoke/both/steady2701では勝利へ改善して停止が17件減る

全32条件・3比較の96差分、全人格/条件/相手群、expired停止・最長未解決停止runを含む悪化一覧は[evaluation.json](evaluation.json)に残す。人格間の勝率を揃えるために本人の軸を動かしていない。

## 因果境界と検証

- 三つの各比較で全32組が少なくとも一度、同じ公開pre-stateから本人の行動を変えた。最初の差では実敵手が同一、差以前の同じ手は実次状態も同一と確認。最初のroute差も別に記録
- 差を作る設定は相手forecast modelだけ。後の局面には、異なる公開状態・本人の実経験・目的切替の影響も含まれる。これを一手だけの直接効果に縮めない
- 96局の2,058実ルール遷移、5,793進捗更新、10,485合法実手、従来root仮説2,160件・候補root標本4,948件を照合。各forecastの遷移数が既定の有限上限内であることも検査
- 学習利用件数・regime reset・全planner仕事量はruntimeの計測値。集計とtrace-on/off一致は照合できるが、原始軌跡には全経験重みイベントや不採用rolloutの全内容を保存していないため、それら内部counterを事象ごとに独立再計算したとは主張しない
- 529 tests、515 passed、14 optional skips、失敗0。新たなsampler/harness29検査。compileall、diff --check成功
- 独立事前レビューは旧forecastを読み込んで24公開状態×通常/recoveryの48比較を実施。新しい監査config欄を除いて元のdefault出力と完全一致。3,200の潜在phase列挙で4標本の目標priorも別計算。[preflight_review.json](preflight_review.json)

独立の最終レビューでも、2,058実遷移・5,793目的更新に加え、保存された34,529モデル遷移と70,346相手行動を別実装のsamplerで再計算した。全96組の最初の差、移動/勝敗/停止/stall、集計率、悪化一覧、凍結hash、4費用局のtrace-off一致も照合成功。[independent_review.json](independent_review.json)。不採用rollout全体の独立再計算は含めない。

## 推奨と再現

既定はfixedを維持。新しいAPIは明示的な `TacticalControl(opponent_model='goal-uniform')` の実験用に限る。今回の範囲では方式・重み・標本数を再調整せず、追加seed探索もしない。

次の設計上の問いは、目的の選択肢を増やす効果と、射撃/移動等をsoftにした効果を分けられるか、そして衝突回避で得た局所利益を目的停滞・勝利喪失へ変えない接続を作れるかである。これらは今回の成果として主張せず、新しい方式の自動追加もしない。

    python -m unittest discover -s tests -v
    python -m reflex.goal_gameplay_experiment preregister --output reflex_artifacts/new_goal_gameplay
    python -m reflex.goal_gameplay_experiment run --output reflex_artifacts/new_goal_gameplay --workers 4
    python -m reflex.goal_gameplay_experiment timing --output reflex_artifacts/new_goal_gameplay

既存preregister/出力は上書き不可。前の予測試験は別の凍結source snapshotであり、その不成立をこの実対戦に合算しない。約28MBの実軌跡は生成物として除外し、[verification.json](verification.json)へhashを保存した。
