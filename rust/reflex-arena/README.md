# reflex-arena（研究用）

3v3戦闘、4人ハゲタカ、4人の協力・取り分競争に、同じ人格・実学習・計画保持を接続する。既存Pythonゲームの主要ルールを使った小型Rust環境であり、全機能の移植ではない。安定版v0.1.0の採用構成ではない。

## 実行

リポジトリ直下でビルドし、有限回の対戦を実行する。Colab、GitHub Actions、定期実行は使わない。

```sh
cargo build --release --manifest-path rust/Cargo.toml -p reflex-arena
python tools/run_arena.py --output results/my_arena --seeds 4 --workers 2 --horizon 6 --second-moves 0 --max-regret 1 --scenario-batches 3 --intent-sharing proposals --reference frozen --modes reflex challenger planned
python tools/arena_replay.py results/my_arena --out evidence/arena/replay.html --summary evidence/arena/summary.json --view-modes planned
```

`output` は新規フォルダを指定する。CLIの既定値は `reflex`。全員が即時判断と1手の合意評価を使う。`planned` は全員が計画、`challenger` は一チームまたは一人だけ計画を使う。計画の既定上限は6手で、常用の採用は未達。全員が実結果から学ぶ。性能比較は同じ乱数・人格配置の `reflex` と `challenger` の対象者について行う。全員自己対戦の勝率平均で優位性を主張しない。

`--reference frozen` が比較の既定。reflexは全員、challengerは対象者以外を従来の即時判断（目的帯0.15、1手、予定共有なし）に固定する。変更された本人と、変更されていない相手を同じ対戦に置く。`matched` は過去の切り分け再現用で、対照にも指定した目的帯や共有方式が作用する。

リプレイへ複数フォルダを渡す場合、同じ対戦は先頭のフォルダを優先する。集計は選択された全データから作り、出典を記録する。`--view-modes planned` は表示だけを全員計画へ絞る。`--summary` は出典の試験集が完走していない場合、または同じ対照組の実行バイナリが異なる場合に拒否する。

## 接続

ゲーム側は `ArenaGame` を実装し、合法手、公開観測、実結果の意味、公開目的値、公開情報だけから作る予測世界を供給する。`advance` は全員の選択を同時に解決し、外部へ副作用を起こさない。`model_world` に秘密の札順・相手の人格・未実行の選択を渡さない。

戦闘の準備効果は既存Python版の公開地形・射線・拠点距離から差分で作る。原版の別経路選択は未移植で、選択経路にはミッション全体を使う。外部の目的値・勝敗規則は変更しない。動くたびに人格報酬を与えない。ハゲタカと協力競争は別の実効果を供給し、共通Plannerにゲーム名の分岐を足さない。

個体ごとに `Owner`、`Planner`、`Beliefs` を持つ。`propose_with_beliefs` → ゲームの実行 → 公開された行動の観測 → `resolve` の順で呼ぶ。提案は捨てられる。実行しなかった結果を `resolve` へ渡さない。モデル内の本人と他者予測は隔離され、実経験へ混ざらない。

`behavior` は本人が観測できる他者の合法行動・行動分類・状況・初期モデルを返す。分類の意味はエピソード中固定。実際に観測した分類で相手ごとの予測を更新する。元の3モデルが全て外れても経験分布から学べる。ハゲタカの入札は同時選択後に公開し、事前には渡さない。

通信可能な相手は `partners`、合法な共同案は `offers` でゲームが指定する。各人が `consent` で独立行動と共同案を自分の人格順序で比較し、`negotiate` が全参加者の同意した案だけを選ぶ。効用を合計して誰かを従わせない。合意は現在の一手だけ有効。次の手では継続・拒否を選び直す。対照の即時判断NPCにも同じ手段を渡す。

`--intent-sharing proposals` は既存の通信を計画へつなぐ。最初に各人が独立の即時判断を提示する。現在の `Intentions { tick, choices }` を受け、`public_input_with_intentions` / `propose_with_intentions` で修正を評価する。受信先はpartnersだけで、敵・欠落・非法・古い予定は拒否する。予定を仮定するのは初手だけ。修正は関係者の初手を含む共同案にし、`consent_allow_indifference` と `negotiate` で全員が受け入れた時だけ実行する。拒否された修正案は破棄し、独立行動へ戻す。共有相手がいない場合は通常の計画判断を使う。

新しい同意入口は、本人の人格段階で同等の効用でも署名を許す。明確な損は拒否する。従来の `consent` は厳密な改善を要求するまま。双方の候補は同じ人格で評価される。

`--planning-protocol independent` は独立計画の比較用。本人の計画を実行候補にし、合意しなかった場合もその計画を保つ。既定の `counterproposal` は上記の即時判断からの共同修正。独立方式では共有情報による全候補の再探索を重ねない。戦闘では退行も出ており、独立方式の全面採用はしていない。

共同案は `offer_compatible` と `negotiate_checked` で実行可能性も確認する。後から受け入れた案が先の案を壊す場合は拒否する。ゲームへ渡す予定は参加者全員が知れる範囲だけで、戦闘では味方同士の同じ移動先を拒否する。独立移動や未共有の敵との衝突は世界の通常ルールで解決する。

共有情報で判断を改善する発想は [Multiagent Rollout](https://www.mit.edu/~dimitrib/Multiagent_Rollout.pdf) を参照した。ここでは個別効用と不完全な予測を使うため、同論文の改善保証をそのまま適用しない。

`Owner::prepare_estimated` は相手モデルの外れを受け付ける入口。既存の `prepare` は既知の条件付き規則との矛盾を拒否する。実結果を見てから二つを切り替えない。CLIの現行契約は `arena-<game>-estimated-model-v7`。協力競争の安全効果は健康・備蓄による安全不足の改善量で、単独行動への定額加点はしない。準備進捗には戦闘の公開準備評価、他ゲームの目的値を渡す。失敗は既存の状況識別で分ける。相手モデルの休息・拠点到達後の維持も修正した。確保済みの拠点は、離れても目的値上の進捗を失わない。旧契約の保存を引き継がない。

世界・Owner・Planner・Beliefsを同じ確定時点で保存する。復元したOwnerに対してPlannerを復元する。Planner保存v4は人格・設定・実学習状態に結び付く。旧形式は拒否する。Beliefsはゲーム・エピソード・観測者・行動分類を照合する。失敗時に世界だけ進めない。CLIは全員の更新・保存復元が通ってから一括確定する。一括保存用の製品APIは未提供。

## 範囲

- 全合法初手、最大8候補の二手目、その後の学習する本人の即時判断を、最大32手まで試す。現在の比較は6手・9標本。全深さの木探索でも、将来の本人が毎手この探索全体を繰り返す計算でもない。
- `--second-moves 0` は固定二手目を省く比較用。`--max-regret` は人格段階内の目的差の許容割合（既定0.15）。0〜1で、通常継続だけなら1で目的の足切りを外す。人格係数と勝敗規則は変更しない。この2変更だけで長期判断が安定するという結果は出ていない。
- `--scenario-batches` は3標本を1組とした組数（1〜4、既定1）。追加組も同じ候補間で共通乱数を使う。相手や本人のモデルは変えない。初期の候補制約と二手目候補生成は従来の1組を使う。
- 共通に予測できた準備手順を保持する。違法化・見込み消失・達成・期限で撤回または完了する。保持中の比較候補は保持手と通常手に限る。
- 目的の許容損は、同じ人格の候補間の差から上限を決める。人格係数は書き換えない。
- 他者の行動観測回数と予測精度を区別する。相手の選択先は分類内で粗く配分し、将来の合意形成も正確には予測しない。
- 全5性格は固定入力。欲求と価値効果はゲームで意味がある範囲を接続する。ハゲタカには空腹などを作らない。全価値の表現、人間らしさ、未知ゲームへの転用は未達。

`--beliefs joint --coordination none` は旧共同モデルの比較用。通常は `individual` と `consent` を使う。監視用の毎ステップハッシュは試走に入れず、同じ予測入力と履歴の計算を上限付きキャッシュで再利用する。

実対戦の結果と限界は [REPORT](../../evidence/arena/REPORT.md)。構造検査は `cargo test --manifest-path rust/Cargo.toml --workspace`。
