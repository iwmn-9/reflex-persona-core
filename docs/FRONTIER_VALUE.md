# 打切り局面の将来価値

`ClosedLoop(..., frontier=...)` は、短い条件付き探索の先の目的値を補う任意の接続。通常の反射と、`frontier=None` の探索は従来どおり。採否と実測値は [検証報告](../evidence/frontier_value/REPORT.md) を正本とする。

## 契約

- ゲーム側が公開状態・合法手・遷移・目的の意味を提供する。実ゲームの未来の乱数や未公開の変化を予測器へ渡さない。
- `identity` と `evaluate(public_world, resolved_owner)` を持つ評価器を接続する。入力は複製され、実行中の本人の記憶を更新しない。評価器・コールバックは同じ宣言・入力に対して純粋に動作し、意味や学習済みパラメータを変更したら `identity` も更新する。
- 出力は `EndpointEstimate`。正規化した `(確率, 目的値)`、推定元、推定内で終局した割合を明記する。目的値はゲームが宣言した同じ `[-1,1]` の尺度。悪い結果も分布に残す。
- `None` はその局面を推定できないという辞退。元のゲーム側の途中代理値を使う。辞退と採用の件数を観測する。一部だけ辞退すると、異なる質の評価が比較される限界がある。
- 実際に探索した状態は `running` のまま。推定した終局を確定勝敗に書き換えず、想像した経験を学習履歴へ入れない。確定済み終局では評価器を呼ばない。
- **補うのは目的値だけ**。探索区間を越えた欲求・主義・関係などの効果列は追加しない。既存の区間内の人格評価・主義の優先・目的の許容幅は維持する。将来の人格的利益を全部比較したという意味ではない。

`PolicyTail` は探索終了時点の同じ本人を複製し、追加の木を作らず、指定した公開シナリオごとに反射方策を動かす。欲求・学習・関係・進展のフィードバックは通常と同じ所有者へ適用する。上限までに終局しなかった試走は途中代理値を残し、終局率にも反映する。シナリオ数・試走長は独立に有界。探索木のノード予算にはこの試走回数を含めないため、総仕事量を別に考慮する。

この反射継続と、実行時に再び探索する本人は異なる。正確なモデルを使っても、反射継続での結果予測が実行結果と一致する保証はない。前の [終局までの同一本人探索](CLOSED_LOOP.md) の一致条件を、この接続へ流用しない。

完全な公開状態を返す `record` を渡すと、試走途中の結果を有界に保存して再利用する。キーには公開状態・所有者の全保存状態・シナリオ・残り期間を含める。似た状態や平均値への置換ではない。予測器の適用範囲や乱数の独立性を広げる機能ではなく、同じ仮定での重複計算だけを省く。

## 実結果からの学習候補

`TerminalMemory` は、終局まで実行した訓練エピソードの公開数値特徴と最終目的値を保存する比較用の学習器。近い局面を持つ異なるエピソードを選び、その終局結果の分布を返す。同じ長い試合の多数の局面が何票も持たない。標準化も各エピソードの総重みを等しくする。保存復元と幾何的な対応範囲の判定を持つ。

訓練データの実体性と公開性は収集側の責任。未来の予測を実結果ラベルへ混ぜない。目的・特徴・ルール・継続方策の版を `reference` に束ねる。`LearnedFrontier` は利用先の `reference` が一致しなければ辞退する。数値が近いだけでは、ルールや目的の意味が同じとは言えない。人間関係の履歴などを入力に含めていない学習器を、それらが判断に効く継続へ無条件に流用しない。

距離の範囲は手動で宣言した支持域の目安であり、正しく校正された確信度ではない。結果のばらつき、推定器の誤差、情報の欠落、未来の方策変更を区別する。この記憶器は汎用的な学習済み重みや、自動的な他ゲームへの転移を提供しない。

## 検証の分離

`tools/run_frontier_value.py` は8系統の公開評価接続へ同じ処理を適用する。ルール名ごとの勝ち手や人格係数の補正は入れない。特徴は既存の共通効果・人格・欲求の数値要約であり、すべての資源や盤面構造を含む表現ではない。独立の実行結果、未使用の乱数、参加人数やルール条件の変更を分けて測る。研究用の `memory` 群は意図的に同じゲーム内の条件変更へ広く転用し、その失敗を保存する。これを利用先の対応範囲として推奨しない。

`tools/probe_frontier_predictions.py` は全推定器を同じ実局面で比較し、各エピソードを等重みにして終局に対する CRPS を測る。対戦中に各方式が訪れた別々の局面の誤差を、純粋な予測性能の比較へ使わない。対戦の成績は別に評価する。

`tools/probe_frontier_graphs.py` は小さな公開グラフで全分岐を列挙し、打切り代理値、有限標本の継続、正確な反射継続、終局までの同一本人探索を比較する。`tools/probe_frontier_connections.py` の25接続の検査は、全ゲームでの強さの証明とは別。

`tools/probe_frontier_rankings.py` は最初に選択が分かれた局面で候補を固定し、別の64シナリオで同じ反射継続を終局まで試す。`tools/probe_frontier_budget.py` はその局面を使う追試であり、新しい独立試合ではない。どちらも未知の実デッキや別の継続方策に対する因果的な正解とは扱わない。

`tools/run_frontier_rollouts.py` は、木を一手にして、その先へ8本の長い試走を付ける別構成を8系統で実行する。二手の木との比較なので、標本数だけでなく、区間内の人格効果や目的値の時間重みも変わる。標本数だけの因果効果とは解釈しない。

`tools/probe_frontier_horizon.py` は No Thanks! の既存の16局面で、木と標本数8本を固定し、試走の長さだけを16手・64手に変える追試。実際に終局へ届いた割合と、独立した64シナリオの反射継続での候補順位を確認する。試走途中の代理値が残る問題と、標本数・将来の再判断による問題を分ける。

`tools/analyze_frontier_value.py` は保存済みの全登録実行を照合する。準備のランダム手で既に決着したケースは残すが、NPCの判断・強さの分母から除く。中断後の再開は同じ登録IDを引き継ぎ、完了行を二度数えない。計算結果を変えない省略についても、凍結した旧出力との行動・結果・所有者状態・予測分布の照合を行う。

## 調査から借りた考え方

[MVE](https://arxiv.org/abs/1803.00101) は短いモデル内の展開と価値推定を組み合わせる。[STEVE](https://arxiv.org/abs/1807.01675) は複数のモデル・価値推定器を用いて展開の長さを調整する。本実装はその深層強化学習手法の再実装ではなく、「打切り地点の価値とモデル誤差を分けて検証する」という考え方を採用したもの。単一の試走内の勝敗分散を、モデルの信用として重み付けする処理は入れない。
