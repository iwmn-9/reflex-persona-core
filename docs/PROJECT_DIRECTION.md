# 人格NPCの目標と開発方針

目的は、異なるゲームの対戦相手や世界の住人として使える人格的な判断の土台を作ること。
同じルール・観測・能力の範囲で、その人物なりに合理的に動き、経験から手段を変えられることを目指す。
勝率最大化、全員を同じ最強戦略にすること、新機構の数、実験量そのものを成果としない。
現在の停止状態・採用構成・未達部分は [STATUS](STATUS.md) が正本。

## 守る条件

1. **人物の軸を保つ。** 性格と有限の主義・価値観は安定した傾向として扱う。
   主義の強さと固執の違いを表現し、本人に意味がある犠牲・妥協を許す。成績に合わせて人格を書き換えない。
2. **状態は経験で動く。** 欲求・感情・記憶・予測を実観測に基づいて更新し、現在の判断へ同時に作用させる。
   想像した未来の経験を実記憶へ混ぜず、欠測を失敗に変換しない。
3. **最低限の賢さを守る。** 人格による支払いと、予測・評価・接続の不備による損を分ける。
   無意味な停滞は避けるが、利益のある待機や準備まで禁止しない。勝率の均等化で個性を消さない。
4. **自分の目的に向けて適応する。** 情報が少ない時は人格に沿って合理的に動き、
   情報が増えれば他者や環境への見込みを更新する。有利な方針を対策のためだけに捨てない。
   単発の不運、相手の変化、自分の計画変更を区別して学び直す。
5. **個体を独立させ、多数に接続できる構造にする。** 通常判断と重い読みを分け、
   NPC間で乱数や経験を混同しない。今は成立を速度より優先しつつ、全NPCへの常時巨大探索を必須にしない。
   速度測定と判断品質の検証を取り違えない。
6. **ゲーム固有の有利手をコアへ埋めない。** ゲーム側は観測・合法手・ルール・目的・結果の意味を供給し、
   コアは評価・選択・学習・再計画を担当する。検証ゲーム名や行動名による補正は禁止。
7. **対戦相手・住人として面白いことを目指す。** 行動の軸が見え、同じ攻略が永久に通じない存在にする。
   利害から葛藤や協力が生まれる余地を持たせる。誇張と省略を使い、判断へ影響しない細部や
   内部状態を増やすことを人間らしさと混同しない。行動差や勝率だけで面白さの達成とはしない。

人間は目的と感触を伝える。軌跡の鑑定や心理係数の設計を人間へ丸投げせず、
開発側が癖・葛藤・状況変化への対応を実行例から評価する。

## 改修の選び方

利用者が改善を再開した時も、既存の人格・学習・予測・再計画の接続と長期安定を優先する。
新機能を足す前に、目標からの不足と具体的な失敗を一つ特定し、既存の機構で直せるかを調べる。
実装・実験はPython。ほぼ固定できた完成単位だけをRustへ移す。

必要な因果診断で、予測の外れ、標本による揺れ、長期利益の数え落とし、人格の選好を区別する。
短い局面の改善は診断であり、長期品質の合格ではない。一方、長い計算を回すこと自体にも価値を置かない。
原因を絞った後に、固定した人格・世界乱数・実学習履歴による長期比較と必要な独立確認を行う。

登録済みの不利な条件を削除せず、結果を見て乱数や対照を替えず、途中を完走扱いにせず、採用基準を緩めない。
元の安定版と不採用の証拠を維持する。研究候補の監査では、その候補の凍結された事前基準を使う。
安定版の基準は [採用決定](../evidence/stable_release/adoption.json) と
[登録時の基準](../evidence/long_horizon/continuation_selected_confirmation_acceptance.json) にある。

停滞したら同じ計算・調整を増やさず、否定済みの仮説と残る原因を整理して方法を変える。
監視・復旧・文書追加の成果は運用上の成果として区別し、知能の進歩として報告しない。
報告では「目標に何が近づいたか」「何を得て、何を採らなかったか」「何が未確認か」を簡潔に示す。
