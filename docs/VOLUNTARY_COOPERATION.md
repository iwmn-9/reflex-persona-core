# 状況に応じて自分たちから組むための任意接続

目標と合否の正本は [開発方針](PROJECT_DIRECTION.md#協力する能力と協力を選ぶ条件)。`reflex/cooperation.py` は、所属や共通目的が先に決まっていなくても、各本人の判断から提案・拒否・別案・合意を作る任意経路。Pythonで研究を続ける。通常のPolicyや既存チーム選択を置き換えるものではない。

## 誰が何を決めるか

ゲームは、本人に見える状態、実行可能な役割の組合せ、その結果のモデル、通信の機会を用意する。コアはゲーム名、協力という行動名、勝つための専用加点を持たない。交換・共同警戒と、既存の共有材料を使う建設ゲームに同じコアを接続する。

1. 各本人が、独立した案と共同案を、同じ目的・時間幅・単位で比較する。`evaluate` は既存のPolicy、固定人格、現在の欲求・判断状態、任意の相手別評価を使う。相手の人格・私的記憶は受け取らない。
2. 独立案より本人の評価が高い共同案だけを、順位付きの `Ballot` として伝える。数値得点や人格は通信処理へ渡さない。物質的な損を本人が納得して引き受ける案は残る。
3. `negotiate` では、任意の未完了手順をまず全員の新しい意思で再確認し、それから未参加の本人が新しい案を希望順に提案する。必要な全員がその案を参加可能と伝えていれば成立する。拒否されたら別の役割・相手を試し、成立しなければ独立案を実行する。
4. 合意は現在の１手についてのみ有効。game・episode・tick・公開機会のrevisionを照合し、次の手では状態と欲求を見直して再度同意する。前回の合意から参加を強制しない。

この方式は各人の独立案を下回らない主観的合意を作る。全体効用の最大化、誰もより良い組を望まない安定マッチング、最善の交渉を保証しない。優先順位は明示的で、検証では毎ターン巡回させる。自分より他人の方が得をすること自体は拒否条件にしない。

`continuing` はゲームがまだ完了していないと判定した手順のID。実行可能な候補として再提示し、現在の全員のBallotが認めた場合だけ新規提案より先に継続する。独立案が上回る、強い主義の許容範囲から外れる、機会がなくなる場合は撤回できる。検証の `continued` 構成では、休息という準備だけで終わった共同手順を次へ渡し、役割を実際に１回実行した時点で解放する。環境の不運で結果が悪くても、実行済みなら自動延長しない。

この交換条件は、未完了手順がまだ各本人に有益なら、新しい共同案への乗り換えを完了まで待つこと。今回の準備は１手なので待機は限定される。期間の長い仕事を同じ規則で保留させてよいという保証ではない。ゲームは完了・中止・期限を定義し、人格や状況を無視する永久契約にしない。

## 境界と前提

- `Offer` は２〜８人の役割を宣言する。未知の行動や他人の合法でない手を合意によって作ることはできない。
- １人を同時に複数案へ参加させない。参加者が別でも同じ共有資源を争う場合の物理的な整合性は、ゲームの候補生成・予約規則で扱う。今回の建設接続では同じ材料を使うチーム全員を一つの候補に含める。
- 署名はその手を本人が選んだこと。契約を強制執行するゲーム規則や、将来の反故・欺瞞まで解決する仕組みではない。
- 予測した将来の協力と、実際に観測した相手の行動を区別する。想像した助けを社会記憶へ学習させない。現在の実結果だけを既存の関係記憶へ返す。
- 独立案と共同案の予測の質が違えば、同意が成立しても本人に損が出る。得点上の同意は実利の保証ではない。

## 検証用の先読み

長期NPC接続は、合法な２人の役割を全組合せで候補にする。協力同士だけでなく、取り分の主張や非対称な役割も含む。継続モデルは「その役割を繰り返し、活動力が足りなければ休息する」という限定した条件付き手順。公開接触枠が閉じている期間には独立行動・回復を見積もる。任意の複雑な手順を自動発明する探索器ではない。

主目的は、指定した見通しの終わりに生存していれば期間平均の資源獲得、死亡していれば-1。生理・安全は不足量の実変化、価値・様式は期間平均として運ぶ。１手の対照にも同じ目的の意味を使う。以前の長期検証の「直後の資源獲得だけ」を使った目的と直接同一視しない。性格や主義の係数は変更しない。

１手は公開確率を正確に列挙する。長い条件付き手順は実世界とは別の乱数系列による８標本で見積もる。相手の現在の実選択や未来の乱数は使わない。将来も相手が再同意する確率まで推定したモデルではないので、予測と再交渉後の実行のずれが残る。標本誤差とこの継続仮定を人格のせいにしない。

共有材料の建設接続では、２〜３人の合法な役割の組合せを列挙し、現在の材料から同時に解決した結果を比較する。既存の相手チームの能力方策を予測に使い、相手の実際の未公開選択を使わない。こちらは１手の役割調整で、自由な仲間探しや長期計画の実証ではない。

## 再現

```sh
python -m unittest discover -s tests -p "test_cooperation*.py" -v
python -m tools.cooperation_experiment --output FRESH_COORDINATION --stage confirmation --seed-start 92100 --seeds 4 --arms independent communicate foresight combined --scenarios standard solo_advantage costly_joint change asymmetric
python -m tools.audit_cooperation --root FRESH_COORDINATION
python -m tools.cooperation_projects --output FRESH_PROJECTS --seed-start 92200 --seeds 12
python -m tools.audit_cooperation_projects --root FRESH_PROJECTS
```

新しい出力先を指定する。登録した条件・ソース・全軌跡を残す。合意率だけで採否を決めず、条件別の生存・資源・悪化、本人の代案、拒否、固定人格を検査する。実験結果と採否は [検証報告](../evidence/voluntary_cooperation/REPORT.md) に置く。
