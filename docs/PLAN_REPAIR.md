# 目的を保った計画の修補

任意で有効にする実験的な部品。既定は `repairs=0` のまま。修補が選ばれることや、予測上の評価が高いことを、実際の判断が常に良くなる保証にはしない。採否と改善・退行は検証報告に分けて記す。

目的はゲームが定義し、計画はその目的へ向かう仮説として扱う。手順の同一性を守るために目的や人格を犠牲にしない。実行済みの手を過去へさかのぼって変更せず、次の公開局面から残りを評価し直す。

既存の `PlanIntention` が保持する所有者・固定軸・目的・時間単位と、全モデル枝で共通の残り手順を利用する。`search_forecast(..., retained=..., repairs=24)` は、新しい探索案と残存案に加えて、一箇所を差し替える有限個の案を作る。根と先の手順の両方を修正対象とする。候補は各位置を順番に巡って生成し、ゲーム固有の行動名を優先しない。

候補の行動は予測した公開局面の合法集合から取る。各案は全モデル枝で同じ手順として再評価する。枝で先の手が使えない場合は、既存の観測に基づく反射へ戻る。旧計画の最初の手が現在使えなくても、合法な先頭へ替えて残りを試せる。未知の将来を確定した事実として保存しない。

目的の評価、本人の主義・欲求・採点、現在の進展制約を従来どおり適用する。`RevisionPreference` は目的と本人の採点が両方同点の候補間だけで変更の少ないものを選ぶ。切替コストは加えない。既存の `ArrivalPreference` が防ぐ「全モデルで達成できる残存案より、目的の利益なく達成を遅らせる変更」は維持する。全面的な組み直しも候補に残るため、長い時間をかけて元の手順が全て置換されても目的の同一性を失わない。

実際に選んだ最初の手だけを実行し、その後で残りの共通部分を記録する。予測中の消費・修正は本人の実経験、学習記録、実際の欲求圧力へ合流しない。目的や時間単位が変更されたら旧手順は持ち越さない。別人物や固定軸の違う人物へ引き継ぐ入力は拒否する。

今回の接続は本人一人が持つ手順と `DecisionLoop`。共同計画への多人数の同意・役割の約束・撤回は未接続。予測側は残存手順と観測時の反射を使うため、未来の本人による外側の全再探索を厳密に予測するものでもない。修補候補の追加だけで全般的な知能や勝率の向上とは扱わない。

```sh
python tools/run_plan_repair.py --root FRESH_STUDY --stage confirmation --start 10040 --seeds 2 --workers 2
python tools/analyze_plan_repair.py --root FRESH_STUDY --workers 2
```

再現は新しい出力先を使う。数値ソースを実行前に凍結し、全実行手を別の世界台帳で確認してから、凍結コードから試合全体を再実行する。結果・採否は [plan_repair](../evidence/plan_repair/REPORT.md) を正本とする。
