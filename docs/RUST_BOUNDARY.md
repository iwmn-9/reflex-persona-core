# Pythonで検証し、採用した部品をRustへ移す

Pythonを実験・審判・比較の正本として残す。仕組みと入出力を確かめた実行部品をRustへ移す。研究モジュールを一括で移植して固定する方針ではない。

## 今回確認したこと

`tools/rust_policy_probe.rs` は、検証済みの数値入力を受け取る通常の `Policy.decide` 計算の独立した試作。Rust標準ライブラリだけを使う。欲求の優先変更、主義の3方式、危険の扱い、経験に関する入力、読みの採否、近接候補の確率選択、個体別SplitMix64乱数、次の判断状態を比較した。

20意味事例、4診断ゲームの128初期局面、乱数生成した256入力、最大256候補を含む入力、同点、64手×16系列を含め、Pythonとの5,124判断の比較で選択・離散状態・乱数が一致した。採点等の最大絶対誤差は約1.78e-15。これはWindowsの標本比較であり、全ての浮動小数の境界での一致、速度、全ゲーム、全機能の移植完了を保証しない。[数値と出所](../evidence/rust_port/result.json)。

この試作の入力読み取りは検査用の有効入力を前提とする。ゲームへ公開するライブラリAPIではなく、不正入力の検証や所有者チェックを代替しない。Python側のJSON検証・正規化・ハッシュから得た64bit種を受け取る。社会評価、単位換算ReturnFrame、学習記憶、先読みは試作に含めていない。

## 実装へ移す順番

| 部分 | 判断 |
|---|---|
| 通常の数値採点・個体別乱数 | 最初の移植候補。今回、数式と選択の再現を小試作で確認 |
| Populationの個体状態・更新・検証 | 採点と一緒に型を固定する。入力範囲、合法手、所有者、保存復元、並び替え・分割への不変性まで移してから実用APIにする |
| 採用済みの有限関係記憶 | その接続構成が必要なゲームで次に移す。予測と感情的な好悪を混ぜない |
| 学習器、目的評価、探索、ゲーム接続、実験器 | 引き続きPythonで検証。採用した構成だけを個別に移す |

Rust化だけで賢さは増えない。大量NPC向けの配置・並列化・ゲームへの組込みを進めやすくする手段である。現状の大きな費用は状況評価や探索にもあるので、採点部の移植だけでゲーム全体が何倍速くなるとは言わない。

変更の採否は、同じ入力から同じ合法な選択と次状態が得られることをPythonとの比較で確認する。初期移植は64bit浮動小数、整数の桁あふれ規則、同点の順序、乱数の個体分離を保つ。32bit化やSIMD、並列化はその後の独立した変更として測る。

```sh
# Rustコンパイラーが入った環境。未作成の出力先を指定する。
python -m tools.verify_rust_policy_probe --output FRESH_RUST_PROBE
```

正式なRust crate、C ABI、Python拡張、エンジン連携は今回作成していない。PythonからRustを呼ぶ製品経路への切替も行っていない。
