# 用意した仮説の外を学ぶ

`reflex/adaptive_dynamics.py` は、既知のルールの下で、用意した人物類型では説明できない**公開された行動・結果の分布**を学ぶ任意部品。`BeliefKernel` の有限仮説を置き換えて再解釈せず、同じ `ClosedLoop` 接続に使える別のカーネルとして提供する。

ゲーム側が提供するのは、本人が観測できる状態、合法な公開イベント、その結果、観測前に分かる最大4個のカテゴリ特徴、任意の既存仮説。新しい敵の正体や正解方策は渡さない。予測したイベントと実際のイベントの違いから、その場で条件付き分布を獲得する。

## 何を学ぶか

`EventLearner` は既存仮説に加え、特徴の部分集合ごとに経験から分布を作る。「状況を無視した頻度」「状況だけで分けた頻度」「状況と直前行動の組合せで分けた頻度」などを同時に比較する。特徴の意味や勝ち手を共通コアに書かない。各組合せの中身は実観測で初めて作られ、用意した仮説の混合では表現できない分布も学べる。

既定では直近8・32・128観測の記憶を比較する。各予測器を、**その結果を覚える前の予測確率**で採点し、当たり方に応じて混合を更新する。古い成功で他の候補が永久に消えないよう、少量の重みを事前配分へ戻す。一定回数外れたら全消去する仕様ではない。

一回の不運と変化の原因を確定診断する機能ではない。短期・長期・条件付き予測の支持が、その後の観測に応じて移る。重みを「性格の真実」「変化した確率」「校正済みの信用」とは呼ばない。既存仮説を保つ価値と新しい規則を学ぶ価値には、初動の慎重さ・追従の遅れという得失がある。

合法な選択肢が違う局面の観測は別に扱う。選べなかった手が出なかったことを好みと誤学習しない。その代わり、合法集合が頻繁に変わる環境では経験を共有しにくい。語彙・カテゴリの設計はゲーム側の責務で、連続値の自動離散化や未知の特徴発見は含めない。

期間は、この観測者へ届いた全公開イベントの個数で数える。強制された一択も時間を進めるため、長く再訪しない状況の経験は窓から落ちる。長期に保存した技能や、状況ごとに別の時計を持つ記憶ではない。混合の小さな事前配分への回帰も時間ごとに適用され、無情報の一択を根拠に特定の仮説を支持するものではない。

## ルールと未知の振る舞いの境界

`PublicEvent(symbol, public, flow)` は既知のルールで起こりうる**区別可能な公開結果**を表す。隠れた原因ごとに、本人には同じ結果を別の記号として渡してはいけない。曖昧なイベント分割は拒否する。複数の相手に相関があるなら、合法な同時行動を結合したイベントとして扱い、勝手に独立化しない。

既存の人物仮説が確率ゼロにしていた合法イベントは、経験モデルから正の支持を持ち、実際に起きれば学習する。ルールの列挙自体にない結果は `UnsupportedObservation` として拒否する。ゲームに存在しない手や効果を自動生成してごまかすことはしない。未知のルール・新しい知覚能力まで自力で発明する仕組みではない。

## 接続と保存

1. `EventLearner` に観測者・意味の識別子、特徴名、既存仮説名を与える。
2. `AdaptiveKernel` に `events(public, action)`、`features(public, action)`、`models(public, action)`、公開状態の保存関数を接続する。これらは純粋で、実際の隠れた方策・未来の乱数を読まない。
3. `kernel.start(public)` で本人の知識状態を作り、`kernel.forecast` の分布から候補効果を作る。通常の反射にも `ClosedLoop` にも同じ予測を使える。
4. 実行後は `kernel.reveal` に実際の公開状態と効果を渡す。戻り値を次の知識状態にする。古い状態・別個体・想像上の分岐は変更されない。
5. `record` / `restore` を同時点の `DecisionLoop` と一緒に保存する。モデルの意味が変わったら識別子を変える。同じ観測を二重登録しないことは呼出側の実行契約。純粋な状態APIなので古い状態を再生すること自体は禁止しない。

探索中も、各公開結果で複製した記憶を更新し、その後の本人の選択を評価できる。`update=False` は将来の学習だけ止める比較条件。実行時には更新するカーネルを使う。既存の固定人格・主義・欲求・感情の係数をこの予測器が変更することはない。頑固さによる主観的解釈との統合は未実施。

## 採用範囲と研究

通常のNPCの既定構成へ一律には昇格しない。予測が当たることと、限られた先読みで目的を達成することは別の評価対象。検証・採否の正本は [実証記録](../evidence/open_model/REPORT.md)。特に予算などの持ち越す資源がある場合、正確な目先の予測を使って使いすぎる可能性を確認する。

通常の反射への接続も、実際に得た記憶を使い、4ゲーム×4人格の冷間・学習後32局面で確認する。4個体ずつの混在バッチと個別選択を比較する機構検査であり、多数NPCの処理速度や実ゲームの勝率を測る試験ではない。

[Herbster / Warmuth, Tracking the Best Expert](https://mwarmuth.bitbucket.io/pubs/J39.pdf) を、成績で予測器を混合し、後から有効になった予測器を復活させる設計の参考にした。本実装は正規化後に事前配分へ戻すlog-lossの混合であり、論文の全アルゴリズムや保証の再実装とは主張しない。[Adams / MacKay, Bayesian Online Changepoint Detection](https://arxiv.org/abs/0710.3742) も検討したが、今回は変化点や原因を断定する変数を増やさず、複数期間の予測を観測前の成績で比較する。ゲームの得点が必ず増えるという保証は、いずれからも導かない。

悪化した資源配分については、[制約付きオンライン学習](https://proceedings.mlr.press/v162/castiglioni22a.html) と [短い制御期間の先の価値](https://arxiv.org/abs/2104.02863) を調査した。次の設計仮説は、残した資源を将来の機会に結び付けて評価すること。ゲームでは自分の手で相手の資源や将来の機会も変わり、人格評価も単純な報酬和とは限らない。これらの手法の保証をそのまま移せるとは判断しない。今回、資源ごとの補正係数や新しい終端価値推定器を実装・採用した意味ではない。
